# video_api：视频模型调用脚本

`seedance.py` 是"视频模型"这一步的一个**适配器**，对接火山方舟（Volcano Engine Ark）上的 Seedance 视频模型，国际版 BytePlus ModelArk 改两个环境变量也能用。方法本身不绑定模型：换成别的视频模型时，照下面的"统一约定"另写一个适配器，其余步骤（关键帧、剪辑、质检）不用改。

## 统一约定（任何视频模型适配器都应做到）

- **提交和取结果分开**。拿到任务号的那一刻就写进日志，之后程序崩溃、断网、关机都不丢；`poll --pending` 能把所有没取回的任务接着取。
- **一个日志**：`<项目>/gen/video_log.jsonl`，每次 API 调用追加一行 JSON（提交、升级、完成、失败）。它同时是任务登记表，也是花费账本。
- **结果位置固定**：`<项目>/gen/<镜头号>/<任务号>.mov` 和 `<任务号>.last.jpg`（尾帧，可作下一镜的首帧）。实际发送的图片存在 `gen/<镜头号>/sent/`，日志里记 sha256，事后能对上"这条视频用的是哪张图"。
- **先空跑再花钱**：`--dry` 只检查、只打印，不联网；打印时隐藏密钥、图片数据和链接里的签名参数。
- **先算账**：`estimate` 和每次 `submit` 都打印预估费用，并注明价格的核对日期。
- **密钥只从环境变量或 `<项目>/.env` 读**，永不打印、永不写日志。

## 准备

1. 安装 [uv](https://docs.astral.sh/uv/)。脚本头部写明了依赖（PEP 723），`uv run seedance.py ...` 会自动装好，不需要手动建虚拟环境。
2. 在项目根目录建 `.env`，写一行 `ARK_API_KEY=你的密钥`，并把 `.env` 加进 `.gitignore`。不要把密钥贴进聊天或提示词文件。
3. 打开控制台的模型列表，确认账号已开通所用模型，复制**完整的模型 id**（带日期后缀）。和脚本默认值不同时，在 `.env` 写 `ARK_MODEL=...` 或每次加 `--model`。
4. 国际版：`.env` 里加 `ARK_BASE_URL=https://ark.ap-southeast.bytepluses.com/api/v3`，模型 id 用控制台里的（2026-10 时为 `dreamina-` 前缀）。价格表是国内版人民币标价，国际版请用 `--price` 传入自己的单价。

以下命令都在项目根目录运行；不在根目录时加 `--project 路径`。所有相对路径都相对项目根目录。下文 `seedance.py` 指本文件夹里的脚本，按你放 skill 的位置写全路径。

## 常用流程

```bash
# 0. 花钱前先算：5 秒镜头，三种分辨率各多少钱，草稿+升级一共多少（竖版加 --aspect 9:16）
uv run seedance.py estimate --duration 5 --count 12 --aspect 9:16

# 1. 首尾帧草稿，先空跑：看画幅、看请求体、看费用，同时跑提示词检查。
#    输出画幅跟随首帧：1080x1920 的关键帧就是 9:16 任务（打印 "frames normalised to 9:16, from first frame ..."）
uv run seedance.py submit --shot S01 --mode first_last \
    --first keyframes/norm/S01-K00.png --last keyframes/norm/S01-K05.png \
    --prompt-file shots/prompts/S01.txt --duration 5 --draft --dry

# 2. 确认无误，去掉 --dry 真正提交；--no-wait 表示只提交不等（批量之前先请用户看一眼余额）
uv run seedance.py submit --shot S01 --mode first_last \
    --first keyframes/norm/S01-K00.png --last keyframes/norm/S01-K05.png \
    --prompt-file shots/prompts/S01.txt --duration 5 --draft --no-wait

# 3. 取回所有未完成的任务（可随时中断，重跑会接着取）
uv run seedance.py poll --pending

# 4. 用户看过草稿、选定后，升级成 1080p（内容不变、不重抽）；放行前请用户看余额
uv run seedance.py upgrade S01=<草稿任务号> S04=<草稿任务号> --dry
uv run seedance.py upgrade S01=<草稿任务号> S04=<草稿任务号>
#    或者直接读批准账本（只认"镜头 → 草稿任务号"的纯字符串写法，不能有 _ 开头的说明键）
uv run seedance.py upgrade --from-json edit/approved_drafts.json --dry

# 5. 查账：提交了多少、完成多少、用了多少 token、按标价约多少钱
uv run seedance.py log
```

**画幅**：首帧、首尾帧任务不写 `--aspect` 时用首帧自己的比例（输出本来就跟随首帧）；写了 `--aspect` 而首尾帧的比例和它差 5% 以上，就拒发并说明会被裁成多大，确实要裁再加 `--allow-crop`。多参考模式（包括有序关键帧）没有首帧可跟，`--aspect` 默认 16:9：**竖版片每条都写 `--aspect 9:16`**。关键帧先用 `../qc/normalise_keyframes.py --size 1080x1920` 统一到输出尺寸。

多参考模式（产品图 + 场景图 + 一段 3D 预演视频作运镜参考）：

```bash
uv run seedance.py submit --shot S07 --mode ref \
    --image keyframes/norm/M1.png --image keyframes/norm/R1.png \
    --video-url "https://你的存储/previs/S07.mp4" --video-seconds 6 \
    --prompt-file shots/prompts/S07.txt --duration 6 --aspect 16:9 --draft --dry   # vertical film: --aspect 9:16
```

有序关键帧（首帧 + 中间帧 + 尾帧，不带视频；用于颜色必须途经某个状态、或中途会露出新东西的短镜头，见 `references/05-video-gen.md` 第 1 节）同样用 `--mode ref`，按时间顺序给图、不给 `--video-url`：

```bash
uv run seedance.py submit --shot S09 --mode ref \
    --image keyframes/norm/S09-K00.png --image keyframes/norm/S09-K02.png --image keyframes/norm/S09-K04.png \
    --prompt-file shots/prompts/S09.txt --duration 4 --aspect 9:16 --draft --dry
```

提示词里用 `@图片1`、`@图片2`、`@视频1`（英文写 `@image 1`、`@video 1`）指代参考素材，编号按命令行里出现的顺序，图片和视频分别从 1 数起。

## 子命令与参数

| 子命令 | 作用 | 关键参数 |
|---|---|---|
| `submit` | 提交一个生成任务 | `--shot` 镜头号；`--mode first / first_last / ref`；`--first --last`（首尾帧）；`--image`（参考图，可重复）；`--video-url`（参考视频，只能是公开链接或 `asset://`）；`--prompt-file`；`--duration`；`--draft`（480p 草稿）；`--resolution`；`--aspect`（首帧模式默认跟随首帧，参考模式默认 16:9）；`--allow-crop`；`--dry`；`--no-wait` |
| `upgrade` | 草稿升级 1080p | `镜头号=草稿任务号` 若干，或 `--from-json 文件`（`{"镜头号": "草稿任务号"}` 或 `[{"shot": .., "task": ..}]`，例如 `edit/approved_drafts.json`）；`--again`（日志里已升级过也再升一次，会再收费）；`--dry` |
| `poll` | 等任务完成并下载 | 任务号若干，或 `--pending`；`--every` 轮询间隔；`--timeout` 最长等待分钟 |
| `estimate` | 预估费用 | `--duration`；`--resolution`；`--aspect`；`--input-video-seconds`；`--count` 镜头数；`--takes` 每个保留镜头平均抽几次草稿；`--price` 自定单价 |
| `log` | 查看日志和花费 | `--shot` 只看一个镜头；`--tail` 显示行数 |

`submit` 的其他开关：`--audio`（让模型自己出声音，默认关，声音后期单独做）；`--watermark`（默认关）；`--format mov/mp4`（默认 mov）；`--no-last-frame`；`--crop-refs`（参考图也裁成目标比例）；`--task-type auto`（默认 `reference`）；`--allow-markup`；`--extra '{"priority": 5}'`（把脚本不认识的新参数原样并入请求体）；`--no-probe`（跳过提交前对链接的可达性检查）。

## 图片怎么处理

- **首帧、尾帧**：画幅取 `--aspect`，没写时取首帧自己的比例（最接近的支持比例，差 5% 以内）；按它居中裁切，再缩放到该比例的 1080p 尺寸（9:16 即 1080×1920，16:9 即 1920×1080），首尾两张因此尺寸完全一致。比例差 5% 以上不会悄悄裁切：拒发，要裁就加 `--allow-crop`（例如 1080×1920 的竖版关键帧按 16:9 发送，会被裁成 1080×608 的一条再放大）。草稿也按 1080p 尺寸发送，升级时模型复用的是同一组输入。源图比目标小会被放大，脚本会提醒"源图越大细节越多"。
- **参考图**：只缩小、不裁切（避免裁掉产品的一部分），缩到能放进 1080p 画幅（横图 1920×1080、竖图 1080×1920）。加 `--crop-refs` 才裁切。
- 一律转成 JPEG（质量 92，4:4:4 不降色度采样，细线和小字更清楚），以 data URL 发送；透明背景垫白。
- 传入的是 `http(s)://` 或 `asset://` 链接时原样发送、不做处理（例如必须保持原始文件的素材），脚本会提醒你自己确认比例和尺寸。

## 提交前的提示词检查

`submit` 每次都先跑这些检查，`--dry` 时只检查、打印、不联网，所以改完提示词跑一遍 `--dry` 就是检查。它只管格式和任务类型；造光源、熄灯、造机位这几族词和产品机理的禁用词，用 `references/05-video-gen.md` 第 4 节的词族扫描另查。

| 检查 | 结果 |
|---|---|
| 含 `()` `<>` `{}` `【】`（全角也算） | 拒绝。Seedance 2.5 把它们读成音乐、音效、对白、屏幕字幕标记，关掉声音也可能让画面出字。确需保留加 `--allow-markup` |
| `@图片N` / `@视频N` 超出实际附带的数量 | 拒绝 |
| 附带的参考素材在提示词里没被提到 | 提醒（每个素材都应说明"拿它做什么、不拿什么"） |
| 参考模式里出现"替换、删除、延长、续写"等词 | 提醒（可能被模型判成编辑或延长任务） |
| 提示词里写了"生成一段 N 秒" | 提醒（时长是参数，不写进正文） |
| 提示词过长 | 提醒 |
| 时长超出 4–30 秒、草稿却指定了非 480p | 拒绝 |
| 首帧、尾帧和输出画幅差 5% 以上（会被裁掉一大块）；没写 `--aspect` 时首帧不是任何支持的比例 | 拒绝（确实要裁加 `--allow-crop`） |
| 参考模式没写 `--aspect` | 提醒（默认 16:9） |

## 费用怎么估

- 公式（厂商文档）：`token ≈（输入视频秒数 + 输出秒数）× 输出宽 × 输出高 × 24 ÷ 1024`，费用 = token × 单价。实际以任务返回的 `usage.completion_tokens` 为准，只对成功的任务收费。
- 含输入视频时有最低用量。按厂商价格示例，输出 5 秒时输入 2–4 秒的价格相同，脚本据此按"输入至少 4 秒"估算（这是推断，以返回值为准）。
- 草稿流程分两步各自计费：草稿按 480p 收；升级按 1080p 收，单价看草稿那一步有没有输入视频，输入视频秒数再算一次，草稿视频本身不计入。
- 内置价格表（火山方舟在线推理，元 / 百万 token，**2026-10-15 核对**，定价页版本 2026-10-10）：

| 模型 | 输出 480p / 720p，不含输入视频 | 含输入视频 | 输出 1080p，不含输入视频 | 含输入视频 |
|---|---|---|---|---|
| Seedance 2.5 | 70 | 42 | 77 | 46 |
| Seedance 2.0 | 46 | 28 | 51 | 31 |
| Seedance 2.0 fast | 37 | 22 | — | — |
| Seedance 2.0 mini | 23 | 14 | — | — |

  对照：按此表，16:9、5 秒、无输入视频的 2.5 一条约 3.36 元（480p）、7.56 元（720p）、18.71 元（1080p），与厂商价格示例一致。价格常变，用前到控制台核对；套餐、节省计划、资源包的抵扣规则也要先问清楚，`log` 给出的是"按标价"的数，不是账单。

## 出错、重试和续跑

- **查询（GET）**：遇到 429、5xx、断网都会退避重试。
- **提交（POST）**：只在"肯定没建出任务"时自动重试（429、500、503、连接根本没建立）。读超时、502、504 时任务可能已经建了，脚本停下并在日志里记 `submit_uncertain`，请先到控制台的任务列表看一眼再决定是否重交，避免同一镜头付两次钱。
- **结果链接 24 小时有效**，最多下载 100 次。下载失败会记进日志，24 小时内重跑 `poll 任务号` 即可；过期就只能重新生成。
- 草稿任务号 7 天内可以升级；`upgrade` 会读日志，已经升级过的草稿不会再提交（除非 `--again`）。
- 密钥被拒（401/403）会立即停止，并提示检查密钥和地域。

## 模型备注（2026-10 核对，使用前核对最新文档）

Seedance 2.5（火山方舟）在核对时的要点，写进了脚本常量：

- 输出 24 fps；时长 4–30 秒，或 -1 由模型决定；分辨率 480p / 720p / 1080p，无 4K。
- 1080p 的 mp4 是 10-bit HEVC，很多剪辑软件和浏览器打不开，所以默认要 mov（H.264 4:4:4，音频无压缩）。剪辑时再转成常用格式。
- 三种任务互斥：首帧、首尾帧、多参考（参考图 / 视频 / 音频），不能混在一个任务里。首帧和首尾帧任务的画幅只能跟随首帧（`ratio=adaptive`）。
- 多参考：最多 30 张图、10 段视频；参考视频只能给公开链接或 `asset://`，不能 base64，单段 2–30 秒、合计不超过 30 秒。
- 图片：每边 300–6000 像素，宽高比 0.4–2.5，单张小于 30 MB；整个请求体不超过 64 MB。
- 草稿：`draft: true` 必须是 480p；升级时只发草稿任务号和 1080p，提示词、素材、时长、比例等自动沿用，重发会报错；升级时 `output_format`、`return_last_frame` 要重新写，否则回到默认（mp4、不返回尾帧）。
- 含真人脸的参考图 / 视频不能直接上传，会被拒。官方给的路子是同一账号的可信生成物（有时限、必须是未经修改的原文件）、平台预置虚拟人像，或做过真人认证的素材。最省事的做法是关键帧不出正脸。
- 限流（个人账号）：每分钟 180 次请求、同时处理 3 个任务，超出的排队；企业账号更高。

其他视频模型（例如 Kling、Runway、Veo、Hailuo）各有自己的任务接口、计费方式和限制，写适配器时照上面的"统一约定"即可，日志字段尽量保持一致（`action`、`shot`、`task`、`resolution`、`usage`、`cost_cny_list`），这样 `log` 式的汇总可以复用。

uv run test_seedance.py
