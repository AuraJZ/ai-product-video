# audio：终混脚本

`mix.py` 把**音乐分轨**和**音效分轨**合成最终声音，压到网络视频常用的响度，再套回画面。画面流直接复制，不重新编码，画质不受影响。

流程：

```
音乐分轨 ─┐  整体衰减 + 按时间窗口闪避（让路）
          ├─ 相加（不归一化）→ 限幅 → 两遍响度标准化（-16 LUFS / -1.5 dBTP）→ AAC 256k ─┐
音效分轨 ─┘  整体衰减 + 按时间窗口提升                                                    ├─ 成片
画面 ───────────────────────────────────────────── 视频流原样复制 ──────────────────────┘
```

术语：**分轨**（stem）是按类别分开导出的整条音轨，和成片等长；**闪避**（ducking）是在某段时间里把音乐压低给别的声音让路；**LUFS** 是整体响度的单位；**dBTP** 是真峰值，信号真实的最高点。

## 输入

- 分轨可以是任意 WAV：16 / 24 / 32 位整数或浮点、单声道或立体声、任意采样率，会统一重采样到 `--sr`（默认 48000）。ffmpeg 能读的其他格式（flac、mp3 等）也行。
- 有旁白时，把旁白放进音效分轨（或先和音效混在一起）。这里的"音效分轨"含义是"音乐不能盖住的那层前景"。
- 分轨长度和画面不一致时，短的补静音、长的截掉，并打印提醒。
- 只给音乐或只给音效也可以。

## 时间窗口文件（sound/windows.json）

```json
[
  {"start": 12.0, "end": 14.5, "target": "music", "gain_db": -5, "label": "标注出现，音乐让路"},
  {"start": 12.0, "end": 14.5, "target": "sfx",   "gain_db": 6,  "label": "标注提示音加强"},
  {"start": 31.2, "end": 36.0, "target": "music", "gain_db": -8, "label": "产品工作声"},
  {"start": 52.0, "end": 55.0, "target": "music", "gain_db": 0,  "label": "只测量：开场音效"}
]
```

- `target: music` 是压音乐，`target: sfx` 是抬音效本身；`gain_db: 0` 表示只测量、不改动。
- 窗口内是满增益；在 `start` 之前、`end` 之后各用 `--ramp` 秒（默认 0.6）做升余弦渐变，听不出"一下子掉下去"。某个窗口要不同的渐变，可单独写 `"ramp": 0.3`。
- 同一分轨上重叠的窗口按 dB 相加。
- 窗口时间从剪辑时间线里读（剪辑器写的 `renders/<EDL 名>_<W>x<H>.timeline.json`，每个标注、每个关键音效的起止），不要凭感觉估。
- **`gain_db` 写的是这个窗口相对于原始音乐分轨的总量**，不含 `--music-gain` 的整片衰减（两者在脚本里按 dB 相加）。如果音乐分轨在做的时候已经在某段预先压低过，窗口里只写剩下的差额；照搬"在已压过的分轨上再压几 dB"的数字，用在没压过的分轨上就会压不够。参考总量见 `references/07-sound.md` 第 8 节。

## 用法

```bash
# 1. 先只测量：每个窗口里"音效比音乐高 / 低多少 dB"，调整前和调整后
uv run mix.py --music sound/music.wav --sfx sound/sfx.wav --windows sound/windows.json \
    --music-gain -3 --measure-only

# 2. 数字合适了，再渲染成片，同时存一份报告
uv run mix.py --video renders/edl_1920x1080.mp4 --music sound/music.wav --sfx sound/sfx.wav \
    --windows sound/windows.json --music-gain -3 \
    --out deliver/demo_explainer_16x9_90s_zh_v01.mp4 --report sound/mix_report.json

# 只要一条混好的声音（例如交给别人做多语言版），不给 --video
uv run mix.py --music sound/music.wav --sfx sound/sfx.wav --windows sound/windows.json \
    --out sound/master.wav
```

不在项目根目录运行时加 `--project 路径`，所有相对路径都相对它。`mix.py` 指本文件夹里的脚本，按你放 skill 的位置写全路径。

常用参数：`--music-gain` / `--sfx-gain`（整片衰减，dB，默认 0）；`--ramp`；`--target`（目标响度，默认 -16 LUFS）；`--tp`（真峰值上限，默认 -1.5 dBTP）；`--lra`；`--limit-db`（限幅器上限，默认 -1 dBFS）；`--bitrate`（默认 256k）；`--save-stems 文件夹`（把调整后的两条分轨存成 32 位浮点 WAV，方便单独试听）。

## 怎么读测量结果

示例输出（数字为示意）：

```
window                          time s  gain dB                   RMS diff     loudest 60 ms      hits min / median (n)
标注出现，音乐让路              12.00- 14.50  music -5, sfx +6      -21.4 -> -10.4     -12.0 -> -1.0       -9.8 / -6.1 (11)
```

- 所有数字都是"音效减音乐"的 dB 差，箭头前是原始分轨，箭头后是加了全部增益之后。**负数表示这个声音埋在音乐下面。**
- **RMS diff**：整个窗口的平均差。
- **loudest 60 ms**：音效最响的那 60 毫秒，与同一时刻的音乐比。
- **hits**：窗口里每一个音效起音（60 毫秒块的局部峰值）分别和音乐比，给出最差的一个和中位数。短促的提示音整段平均看着改善了，逐个看可能仍然听不见，所以要看这一列：判断要不要提升提示音，以这一列为准，不以 RMS diff 为准。
- 响度标准化对整条混音乘同一个增益，不改变这些相对差；限幅器只会稍微削掉最尖的峰。

调整的顺序：先给音乐一个小的整体衰减（常见 -2 到 -4 dB），再在窗口里闪避，然后**重新测量**。短促的提示音如果仍比音乐低 8 dB 以上，继续压音乐会让那几秒"空掉"，改为直接把提示音提高（+4 到 +6 dB）。最后在完整混音上用耳朵确认，不要只听单独的分轨。

案例：某产品片中，用户反馈"音乐太强"。实测产品工作声那一段音效比音乐低 13.2 dB（这时音乐分轨在这一段已经预先压低了 2 dB）；音乐整体 -3 dB、该段再让路 -6 dB（窗口内合计 -8 dB）后变成低 4.2 dB。标注提示音按整段平均改善了 8 dB，但逐个按 60 毫秒测仍低 10–16 dB，于是把提示音本身 +6 dB，多数变成低 4–8 dB，交付时整片 -15.9 LUFS。

## 响度目标

- 默认 -16 LUFS 积分响度、-1.5 dBTP 真峰值，适合大多数网络视频和演示场合，换平台时音量跳变小。
- 各平台、电视台、影院的标准不同（例如有的平台按 -14 LUFS 归一化，广播常用 -23 或 -24 LUFS），按投放渠道用 `--target`、`--tp` 调整，使用前核对该渠道的最新规范。各场景的数值表见 `references/07-sound.md` 第 9 节。
- 渲染完脚本会用 ffmpeg 的 ebur128 再测一遍成片，偏离目标超过 1 LU 或真峰值超标会打出 `WARN`，结果写进报告的 `loudness.final`。

## 工具备注（2026-10）

- ffmpeg 来自 `imageio-ffmpeg` 自带的二进制，无需另装；想用系统里的 ffmpeg，设环境变量 `IMAGEIO_FFMPEG_EXE=ffmpeg 路径`。
- 响度标准化用 ffmpeg 的 `loudnorm` 两遍法：第一遍测量，第二遍带测量值以线性模式处理（整段同一增益，不改变动态）；若线性模式达不到目标，ffmpeg 会自动退回动态模式。
- 限幅用 `alimiter`（attack 5 ms、release 80 ms）。

## 测试

```bash
uv run test_mix.py
```

用合成素材测试：16 位单声道 44.1 kHz 的正弦和弦当音乐（比画面短）、32 位浮点立体声 48 kHz 的点击声当音效（比画面长）、10 秒测试画面。检查渐变曲线形状、窗口前后的 dB 差（预期 +15 dB = 提升 6 + 闪避 6 + 整体 3）、成片响度（ebur128 实测约 -16.1 LUFS、真峰值 -1.5 dBTP）、画面流是复制而非重编码、仅输出音频的路径。
