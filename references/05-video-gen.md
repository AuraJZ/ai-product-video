## 1. 生成模式与按镜头选择

| 模式 | 输入 | 适合 | 风险 |
|---|---|---|---|
| 首尾帧 | 首帧 + 尾帧两张关键帧 + 提示词 | 4–6 秒、只有一个慢速运镜的产品镜头；大多数产品镜头 | 两张图构图略有差异时，模型会在中间偷偷叠化；运动中新露出的东西由模型编 |
| 只给首帧 | 首帧 + 提示词 | 结尾不重要的氛围镜头；尾帧画不出来时 | 结尾不可控，可能漂移 |
| 多参考 + 灰模视频 | 有序关键帧 + 灰模视频 + 人物设定图 + 产品母版 + 提示词 | 10 秒以上的一镜到底、有人物走位、效果有先后顺序 | 素材越多越要写清每份"取什么、不取什么"；参考视频的像素会被照抄 |
| 有序关键帧（不带视频） | 按时间排好的首帧 + 中间帧 + 尾帧（通常 3 张）+ 提示词，不给参考视频 | 4–6 秒的短镜头里，颜色必须途经某个指定状态（比如灯色变化不能途经粉色），或运动中会露出首帧里没有的东西；也适合有几个必须到位的中间状态、但没有复杂走位的镜头 | 几张关键帧的缩放必须一致，中间帧同样要过 Gate K；提示词约 500 字 |

每个镜头单独选，写进镜头表：

1. 有人物走位、或者 10 秒以上？→ 多参考 + 灰模视频。
2. 颜色必须途经某个指定状态，或者有必须到位的中间状态？→ 有序关键帧（或多参考）。
3. 结尾构图重要吗？重要 → 首尾帧；不重要 → 只给首帧。
4. 运镜会露出首尾帧都没有的区域吗？会 → 先改运镜（见 03）；改不了就给那一刻画一张中间关键帧，走有序关键帧，不要指望模型补对。

附带客户端没有单独的"有序关键帧"开关：用 `--mode ref`，按时间顺序给 `--image`（首帧、中间帧、尾帧），不给 `--video-url`；提示词开头写"以@图片1至@图片3的顺序作为关键帧……"，再逐秒写变化（模板 `templates/prompts/omni_long_take.txt` 去掉视频和人物设定那几句）。

**画幅**：首帧和首尾帧任务的输出画幅跟随首帧，附带客户端不写 `--aspect` 时按首帧的比例处理（首帧比例和 `--aspect` 差 5% 以上会拒发，不会悄悄裁切）。多参考和有序关键帧任务没有首帧可跟，画幅是请求参数，默认 16:9：**竖版片每条都加 `--aspect 9:16`**。

不同模型支持的模式不同，以模型文档为准（第 14 节）。

## 2. 逐秒提示词的结构

视频提示词是**从事实推出来的分镜剧本**，不是氛围描述。结构固定为五段：

1. **任务声明**。首尾帧模式用固定的第一句："首帧就是给定的首帧图片，尾帧就是给定的尾帧图片，镜头从首帧连续运动到尾帧，中间不切镜。" 多参考模式开头逐个说明每份素材取什么、不取什么。
2. **一句话场景**：时间、地点、主体和它此刻的状态。
3. **逐秒分段**：短镜头按每 1 秒一段；长镜头按连续的 2–3 秒一段。每段只写**一个主要变化**，内容包括：
   - 摄影机：方向、速度，**写数字**（"以产品为中心向右环绕，平均每秒约 5 厘米"）；
   - 主体和人物：身体怎么动，具体到手、脚、重心、布料、头发；
   - 效果：这一段效果处在什么状态；
   - 以"结束时……"收尾，写这一段结束时的画面状态。最后一段写"结束时画面与尾帧一致"。
4. **不变的东西逐项写**："产品全程不移动、不变形，只有镜头在动""连接线静止平贴桌面""指示灯亮度保持恒定"。
5. **边界**：效果只在哪里出现；"画面里只有首帧和尾帧已有的物体""除产品自身字样外，不显示字幕、文字或标牌"；有人物时"全程不转头，看不到脸"。

写法规则：

- **数字从事实底稿复制**（见 03 第 4 节），不手写。提示词和灰模视频的时间必须来自同一个来源。
- 外观不再重复描述，关键帧里已经有了。只写变化。
- **用正面描述**。少写"不要……"，多写"保持……""只在……"。边界可以用正面的说法表达："上方空气保持清透"。
- 不写"生成一段 N 秒视频"，不写 4K、8K、电影级、大师作品这类空泛的词。
- 长度：首尾帧约 150–500 字；多参考的一镜到底约 1000–1500 字。
- 每 4–5 秒只安排一个动作高峰。广告片要节奏感时，靠剪辑（多切几刀），不要在单个镜头里加快运镜。

模板：`templates/prompts/first_last.txt`、`omni_long_take.txt`、`bridge.txt`。

一段通用示例（台灯产品的首尾帧镜头，5 秒）：

```text
首帧就是给定的首帧图片，尾帧就是给定的尾帧图片，镜头从首帧连续运动到尾帧，中间不切镜。傍晚的书房，书桌右侧是台灯，灯还没有亮，桌上摊着一本打开的书。
0-1秒：镜头由静止起步，向台灯缓慢推近，平均每秒约推近画面宽度的2%；台灯灯头内侧出现一点暖白色。结束时灯头内侧暖白均匀。
1-2秒：推近匀速；灯光落到书页上，形成一片边缘柔和的暖白光斑。结束时光斑覆盖书页的左半边。
2-3秒：光斑扩展到整本书和书旁的木纹桌面，桌面木纹清晰可见。结束时书页亮度明显高于桌面其他区域。
3-4秒：推近开始减速；墙上出现一圈淡淡的暖色反光。结束时镜头只剩很慢的移动。
4-5秒：镜头减速到停稳，整段推近约画面宽度的8%。结束时画面与尾帧一致。
台灯和书全程不移动、不变形，只有镜头在动。灯罩是哑光金属，本身不发光，光只从灯头下方照出，空气中没有光束和光晕。画面里只有首帧和尾帧已有的物体，没有人，除台灯自身小字外，不显示字幕、文字或标牌。
```

## 3. 效果怎么写：对照表

总原则：

- **从真实的物理来源写**：效果从产品的哪个真实部位出来。
- **按摄影机拍到的样子写**：颜色、落在哪个表面上、反光的样子；可以用拍得到的物理类比（"像被月光照到"）。
- **写清边界和"不是什么"**。
- **用量用肉眼可查的标准卡住**（"桌面木纹清晰可见"），不写"少一点""淡一点"。
- **画面就是宣称**：画面里有雾，观众就以为产品能喷雾；画面里有光，观众就以为那里有灯。产品没有的机理，画面上也不能出现（机理以 `01-intake.md` 的产品事实单为准）。

| 效果 | 这样写 | 不要这样写 |
|---|---|---|
| 常亮的指示灯 | "〈颜色〉指示灯亮度保持恒定，与首帧一致" | "调到最低""慢慢变暗""呼吸"——会被画成熄灭或忽明忽暗 |
| 灯光照到环境 | "墙面上出现一片柔和的〈颜色〉光，从〈光源〉方向慢慢扩开，边缘柔和" | "光束""射线"——会画出舞台光柱 |
| 颜色渐变 | "颜色只沿 深红 → 橙 → 金 → 暖白 单向变化，不回退，不出现粉色" | 只写起点和终点——中间可能经过粉色、倒着走 |
| 表面变凉 / 变暖 | "冷蓝色从〈部位〉沿表面慢慢铺开，像被月光照到；表面仍是哑光的" | "发光""光晕"——表面会变成灯 |
| 材质颜色 | "〈部件〉是哑光的〈颜色〉金属，只反射环境光，本身不发光" | 只写"铜色""金色"——会被画成暖光 |
| 可见的雾或蒸汽（产品真有） | "从〈真实出口〉渗出，最多升到〈参照物〉一半高，上方空气保持清透；桌面大部分和木纹清晰可见" | 只写"雾气升腾"——会冒出蒸汽柱或铺满桌面 |
| 看不见的东西（气味、无线信号、感知） | 不画；或用极简的抽象符号："极淡的〈颜色〉细点弧线，细而半透明，没有光束、射线、图标或数字"，并在字幕里说明是示意 | "扫描线""数据流"——会画成科幻界面 |
| 声音 | "〈颜色〉柔和弧形波从〈声源〉一层层传到〈接收处〉，只朝〈方向〉，不在〈表面〉上向四周扩散"；或者不画，交给音效 | "声波扩散"——没有方向和边界 |
| 液体（倒水、咖啡） | "细而连续的水流从〈出口〉落入杯中，液面平稳上升，没有溅出" | "水花四溅"——会失控 |
| 屏幕内容 | "屏幕保持暗着"；真实界面用录屏或在剪辑器之外做好的界面动画，整屏接进 EDL，要放进画面里的屏幕就在合成软件里先合好 | 让模型画界面——文字会乱码 |
| 有意关灯（状态变化，例如工作结束时指示灯关闭） | "在第〈t〉秒〈指示灯〉关闭，关闭后和〈机身〉同色，之后保持关闭"；关之前的段落照样写"亮度保持恒定" | "慢慢变暗""熄灭""暗下去"——会拖成渐暗或忽明忽暗。词族扫描（第 4 节）若命中"熄""暗下"，这里是有意的，确认后保留 |
| 按键、开关 | 写清"谁在动作"：手指按下〈按键〉之后灯才亮 | 灯自己亮但配一个手按的动作——讲错因果 |

> 案例：某产品片里，提示词写指示灯"调到最低"，灯在第 2.5 秒完全熄灭；改成"亮度保持恒定"才通过。另一处金属件只写了颜色词、没注明"不发光"，被画成了暖光；还有一处可见效果先被画成从顶部直冲的一根白柱，改写出处后又铺满整张桌面，第三次把真实出处、最大范围和"桌面木纹清晰可见"这条肉眼标准都写进去才对。

## 4. 禁用词族

提交前用脚本搜一遍（lint）。**一个词出过一次事，就在所有提示词里搜同一族词，提前改掉**。

| 词族 | 例词 | 为什么 |
|---|---|---|
| 改变任务类型 | 编辑视频、增加、加上、删除、去掉、修改、替换、改成、延长、延续、续写、继续 | 有的模型按提示词意图判断任务类型，这些词会把"参考生成"变成"编辑"或"延长"，导致失败或报错 |
| 保留符号 | 【】 () <> {} 以及全角（）＜＞｛｝ | 有的模型用这些符号表示音乐、音效、台词、字幕 |
| 造机位、造出口 | 全景、拉远、俯视、横移、门口、画面左/右、〈家具〉后方 | 每个空间词都会被执行；位置一律以画面里的固定物为参照（台面、墙、窗、柜子） |
| 造光源 | 发光、光晕、光波、光束、射线、霓虹（用来描述效果或产品本体时） | 会把产品边缘画成灯带，甚至整个产品变成一盏灯。写边界的否定句可以用，而且常常需要："本身不发光""空气中没有光晕和光束" |
| 让常亮的灯熄灭 | 最低、变暗、暗下、熄、呼吸、闪烁 | 会被理解成关灯或大幅明暗起伏 |
| 与机理不符 | 按项目列：产品没有的机理的词 | 写了就会画出来 |
| 空泛词 | 4K、8K、ARRI、电影级、大师作品、超高清 | 没有用，还挤占注意力 |
| 时长指令 | 生成一段 N 秒视频 | 和 API 的时长参数冲突，模型可能多切一刀 |

**两层检查，提交前都跑：**

1. **附带客户端的检查**：`seedance.py submit ... --dry` 不联网，就会跑一遍提示词检查。保留符号（拒发，确需保留加 `--allow-markup`）、`@图片N` / `@视频N` 编号超出实际附带的素材（拒发）、附带的素材在提示词里没被提到（提醒）、参考模式里改变任务类型的词（提醒）、正文里写了时长（提醒）、提示词过长（提醒）。逐项说明见 `scripts/video_api/README.md` 的"提交前的提示词检查"。
2. **词族扫描**：客户端不认识"造光源""让常亮的灯熄灭""造机位"和本产品的机理禁用词。用附带的 `scripts/qc/lint_prompts.py` 扫 `shots/prompts/` 下的所有提示词（上表的词族已内置）；本产品没有的机理，写进一个 JSON 词表用 `--families` 传入。命中只是提醒，边界否定句（"本身不发光"）和有意关灯（第 3 节）确认后保留。它打印扫了几个文件，一个都没扫到时报错退出（路径错了不会看起来像"全部通过"）：

```bash
uv run scripts/qc/lint_prompts.py --project <project>
uv run scripts/qc/lint_prompts.py --project <project> --families work/lint_words.json   # {"not this product": ["喷雾", ...]}
```

## 5. 参考包卫生

**送进视频模型的每一个像素都会被照抄**，包括错误。

- 只放你要它照抄的东西。
- **不放机位和本镜头不同的整屋图**。它会变成模型可以"跳过去"的出口。
- 不放带标注的走位图、带文字说明的 CG 设定图。
- 产品母版在中性灰底上抠图。
- 每份素材都写明用途，以及不能从它身上拿什么（"@图片3只提供产品外观和材质，不采用其背景和构图"）。
- **每张参考图本身的产品细节必须正确**。参考图里画错的线缆、接口，会原样出现在视频里。
- 灰模视频统一灰色、降噪（见 03）。
- 遵守人脸政策（见 04 第 9 节）。
- 图片不超过输出分辨率；文件大小、尺寸、时长都在平台限制以内。

> 案例：某产品片的一段长镜头，结尾写了"摄影机缓缓拉远，收在房间全景"，参考包里又有一张俯视的整屋图。生成结果在第 11.6 秒硬切到几乎就是那张参考图的画面，冻住 11 帧。另一段视频里冒出一根白色圆线，来自一张场景参考图里同样画错的线缆。

## 6. 花钱分两级：480p 草稿 → 1080p 升级

1. **一律先出 480p 草稿**（或模型提供的最便宜预览档）。
2. 审完、拼出粗剪、拿到用户明确同意。
3. **镜头顺序和字幕定稿之后**，才把批准的那几条升级到 1080p。
4. 模型支持"草稿升级"时，用同一个任务原样升级，**不重新生成**。升级后核对：时长完全一致，中间帧和草稿的相关系数在 0.99 以上，这样剪辑点不用重找。
5. 模型不支持草稿升级时，1080p 就是重新抽卡，草稿只能当参考：高清版要重新逐帧审，剪辑点重新定。

1080p 一条通常比 480p 贵 5 倍以上，大部分问题在草稿阶段就能看出来。

**成本记账**：每次调用都记一行日志（镜头、任务 id、模式、分辨率、时长、估算金额）。每批之后报告"已花多少 / 上限多少"。大批量升级之前，先确认账户余额和套餐真实能抵扣的额度（很多节省计划只抵面值，超出部分按量计费，余额不足会直接拒绝提交）。账单用自己的日志独立核对。

## 7. 演练（dry run）与拒发闸门

每次付费提交前先 dry run：只拼请求、不发送，打印提示词、素材表、预估费用、警告和拒发理由。下面任何一条不满足就不提交（标 ★ 的由附带的 `seedance.py` 自己拒发，其余由项目自己的提交步骤保证，见本节末尾）：

- ★ 素材文件不存在；
- 关键帧没有 Gate K 报告，或报告是 FAIL 且没有绑定文件指纹的人工放行记录；
- ★ 链接打不开（提交前探测）；返回的不是对应类型的文件（图片 / 视频）；
- 可信人脸素材被裁剪或重新编码过（和原始文件逐字节比对）；
- ★ 提示词里有保留符号；改变任务类型的词（★ 只提醒）；
- ★ 提示词里的 @图片N / @视频N 编号超出附带的素材数量；
- ★ 首尾帧尺寸不同，★ 首尾帧比例和输出画幅差 5% 以上（会被裁掉一大块）；时间顺序反了；
- ★ 图片、请求体超出平台的尺寸、比例、大小限制，★ 时长超出范围；
- 预估费用会超过预算上限（★ 只打印预估）。

**拒发时修输入，不要绕过闸门。**

本 skill 附带一个视频模型客户端 `scripts/video_api/seedance.py`（目前对接的模型见第 14 节），已经内置其中的提示词检查（第 4 节）、尺寸检查、链接探测和费用估算（参数以脚本自带说明为准）。视频提示词存成 `shots/prompts/<镜头>.txt`，改动时加版本号、保留旧版：

```bash
# cost before spending: 20 shots of 5 s, 2 draft takes each (vertical film: --aspect 9:16)
uv run scripts/video_api/seedance.py estimate --project . --duration 5 --count 20 --aspect 9:16
# dry run of one first/last draft: checks and prints the request, sends nothing.
# The output aspect follows the first frame: 1080x1920 keyframes give a 9:16 task (see "ratio adaptive ... from first frame")
uv run scripts/video_api/seedance.py submit --project . --shot S05 --mode first_last \
    --first keyframes/norm/S05-K00.png --last keyframes/norm/S05-K05.png \
    --prompt-file shots/prompts/S05.txt --duration 5 --draft --dry
# a ref-mode task has no first frame to follow: give the aspect explicitly
uv run scripts/video_api/seedance.py submit --project . --shot S09 --mode ref --aspect 9:16 \
    --image keyframes/norm/S09-K00.png --image keyframes/norm/S09-K02.png --image keyframes/norm/S09-K04.png \
    --prompt-file shots/prompts/S09.txt --duration 4 --draft --dry
```

`seedance.py` 不读 Gate K 报告，也不比对可信人脸文件。这些项目级检查由项目自己的提交步骤保证：在 `work/` 里写一个包装脚本，先查 `qc/` 里每张输入图的 Gate K 结果和 sha256（FAIL 必须有绑定同一指纹的放行记录），再调用 `seedance.py submit`；或者至少用一张提交前逐项打勾的清单。

第一次花钱：先用最便宜、不需要上传素材的镜头跑通整条链路（鉴权、请求格式、轮询、下载），几块钱就能验证。每用一种新的请求模式，先付费试一条，确认可用再批量提交。每次批量提交之前（不只是高清升级），先报这一批的预估费用，并请用户看一眼账户余额和套餐的真实抵扣额。

## 8. 可续跑的提交与取回

- **提交和取回分成两条命令**。提交成功后，任务 id 立刻写进只追加的日志文件（比如 `gen/video_log.jsonl`），写在任何可能出错的步骤之前。
- 取回按任务 id 查询，断网、会话中断后可以单独重跑。
- 下载的文件名带上镜头 id 和任务 id，同时保存最后一帧（给过渡镜头用）。
- 遇到限流（HTTP 429）或网络错误，自动等待重试，间隔逐次加长。
- 生成结果的下载链接通常有时效（比如 24 小时），完成后马上下载。
- 长批次放在后台跑，每一步结果写到磁盘上，靠已有文件判断进度，接着跑。

用附带的客户端时：`submit --no-wait` 只提交；`poll --pending` 取回日志里所有还没有结果的任务；`upgrade --from-json edit/approved_drafts.json` 把批准的草稿升级到 1080p（先加 `--dry` 看报价；已升级的会跳过）；`log` 汇总任务、token 和估算花费。

用户只有网页或 App 会员、没有 API 时，视频由用户手动生成：交给他一个手动视频包（`templates/prompts/video_pack_manual.md`：上传顺序、设置、提示词、下载后改成 `gen/<镜头>/m-<日期>-<镜头>-<次>.mp4`），每生成一条在 `gen/video_log.jsonl` 补一行；批准账本里直接写文件路径。

## 9. 逐帧审看：每 0.25 秒一帧

**一帧好不代表整条好**，漂移是随时间出现的。每条草稿都要：

1. 拼一张每 0.25 秒一帧的联系表：

   ```bash
   # 4 frames per second, 8 columns; rows x 8 must cover seconds x 4
   ffmpeg -i S05_draft.mp4 -vf "fps=4,scale=384:-2,tile=8x3" -frames:v 1 S05_strip.jpg
   ```

   （ffmpeg 可以从 `imageio-ffmpeg` 取：`uv run --with imageio-ffmpeg python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"`。）

2. 画两条曲线：相邻帧的运动量（灰度差的均值）和平均亮度。
3. 专门找这些问题：
   - 硬切：运动量突然尖峰；
   - **隐藏的叠化**：一段时间里出现两个插头、重影、双层头发——首尾帧模式在两张构图略有差异的关键帧之间常这样做；
   - 定格：运动量接近 0 的一段；
   - 闪烁：指示灯亮度来回跳；
   - 产品漂移：轮廓、字样、接口方向、数量；
   - 效果越界、出现人脸、出现文字。
4. **独立审查必须看生成的原片**，不能只看剪好的成片。剪辑时可能刚好把问题段藏住，也可能刚好漏看。

> 案例：某产品片一条草稿在原片 2.25–3.5 秒出现两个插头和重影，负责剪辑整合的流程漏看了，是独立审查在原片里发现的。最后只用 0–2.25 秒的干净段并放慢。

## 10. Gate V：视频自动检查

Gate V 在升级 1080p 之前跑，和 Gate K 一样有 PASS / REVIEW / FAIL 三档、校准、人工放行（绑定文件指纹）。和 Gate K 一样，它是**项目自己的脚本**，本 skill 不附带现成的判定；附带的 `scripts/qc/strip.py` 已经算好逐帧运动量和亮度、标出硬切、亮度跳变和定格（`--fail-on-flags` 可给批处理用），可以当它的一部分。经验起点（用你自己的已知好、坏样本重新校准）：

| 检查 | 怎么判 | 经验起点 |
|---|---|---|
| 硬切 | 相邻帧相关度骤降 | 相关系数 < 0.5 |
| 叠化 | 某帧接近前后两帧的线性混合，而和两者都不像 | 人工复核 |
| 定格 | 连续多帧运动量接近 0 | 中段定格判 FAIL；结尾 ≤ 1.5 秒的静止判 REVIEW。**设计好的静止不算**：镜头表写明动作停下后保持不动（例如包装照式的片尾镜头、灯关闭后的静物），而 EDL 把这一段裁掉或用 `hold_end` 接住时，按 PASS 记，并在报告里写明依据 |
| 参考图越界 | 某一时刻和某张参考图（非该时刻的关键帧）高度相似 | 相关系数 > 0.8 |
| 指示灯闪烁 | 跟踪指示灯区域的亮度 | 波动 > 5% 要复核（注意：镜头移动时跟踪器可能跟丢，产生误报） |

输出一张每 0.5 秒一帧的总览图，把事件标成红色。

## 11. 重跑纪律

- **用"时间段 + 缺陷"描述问题**："10–13 秒产品边缘像灯带；12–14 秒指示灯闪烁"。
- **只改出错的那几段**提示词，其余不动。
- **一次只改一个变量**，并保留旧版提示词（加版本号），这样才知道是哪个改动起了作用。
- 一个词出过事，搜全部提示词里的同一族词（第 4 节）。
- 给每个镜头设重跑上限（比如 3 次）。到上限就换思路：换生成模式、重画关键帧、缩短镜头、用转场或字幕覆盖，或者**直接弃用这个镜头**，由别的镜头承担它的作用。有些镜头不值得和模型较劲。

## 12. AI 过渡镜头（bridge）

用视频模型专门生成一小段，把两个镜头接起来。

- **什么时候用**：同一空间、同一时刻、画面里没有脸。其他情况用剪辑转场（见 06 的转场表）。
- **素材**：首帧 = 上一镜实际出点的那一帧（逐字节导出，不重新画）；尾帧 = 下一镜实际入点的那一帧。首尾帧模式，时长约 4 秒。
- **运动节奏要和前后镜头匹配**：前后都在动，就写"全程运动、在第 4 秒到位"，不写"减速再停住"，否则接口处会"停一下再走"。
- **入点约 0.04 秒**，跳过和上一镜重复的第 0 帧。出点按实测运动量定，不要目测估。
- 提交时把过渡镜头的 id 当镜头号（例如 `--shot B_S04_S05`），结果就落在 `gen/B_S04_S05/`；批准后写进 `edit/approved_bridges.json`。
- 在 EDL 里给每个 bridge 设**后备转场**（比如 0.6 秒叠化），没批准时自动退回。
- 在生成镜头之前就做转场表，逐个接口写明怎么接。计划里的 bridge 通常只有一部分能用上。

模板：`templates/prompts/bridge.txt`。

## 13. 批准账本

每个镜头最终用哪一条，记在两本 JSON 账本里：镜头记在 `edit/approved_drafts.json`，AI 过渡镜头记在 `edit/approved_bridges.json`。格式是"镜头 id → 批准的草稿任务号"（模板 `templates/approved_drafts.example.json`、`approved_bridges.example.json`）：

```json
{"S05": "<draft task id>", "S07": "<draft task id>"}
```

- 剪辑器按 EDL 的 `ledger_pattern`（默认 `gen/{id}/{task}`，自动补 .mov / .mp4 等扩展名）找到文件；EDL 里不写 `src` 的镜头只从账本取素材（见 06）。没批准的镜头用黑底标牌占位，保证总时长不变。
- 同一个文件直接交给附带客户端升级：`seedance.py upgrade --from-json edit/approved_drafts.json --dry`。客户端只认这种"镜头 → 草稿任务号"的纯文本写法，所以账本里不放以 `_` 开头的说明键。
- 升级完成后，把这一镜的值改成 `{"task": "<草稿任务号>", "src": "gen/S05/<升级任务号>.mov"}`：剪辑器优先用 `src`，草稿任务号留作记录。改成这种写法以后，这份账本就不要再交给 `upgrade --from-json`；还要升级的镜头用命令行 `镜头=任务号`。剪辑器还认媒体路径（例如实拍的 `footage/S05.mp4`），详见 `scripts/edl_editor/README.md` 第 4.3 节。
- 用哪一段（入点、出点、放慢）写在 EDL 里；谁批准的、用户原话、文件指纹写进 `brief/decisions.md` 的决定记录（`10-working-with-user.md` 第 1.5 节）；自动检查被人工推翻时，放行记录写进 `qc/` 的闸门报告。

## 14. 模型备注（2026-10，使用前核对最新文档）

模型版本、价格、限制按月变化。以下是 2026-10 的记录，**使用前一定核对官方最新文档**，并把核对日期写进项目记录。

### Seedance 2.5（字节跳动，火山方舟平台）

- **任务类型由输入和提示词意图判断**：文生视频、首帧 / 首尾帧生视频、全模态参考生视频；全模态参考又按提示词意图分为参考生成、视频编辑、视频延长。这就是"改变任务类型"的词要禁用的原因。
- **提示词里的保留符号**：官方提示词指南用 `()` 表示音乐、`<>` 表示音效、`{}` 表示台词、`【】` 表示字幕。不想要这些时就不要用这些符号。
- **首尾帧**：`first_frame` 和 `last_frame` 两张图；输出画幅跟随首帧（ratio 只能是 adaptive）；时长 4–30 秒或 -1（模型自选）。
- **全模态参考**：参考图 1–30 张；参考视频最多 10 段，每段 2–30 秒，总时长不超过 30 秒；也支持参考音频。
- **单次生成最长 30 秒**；输出 24 fps。当时 1080p 默认输出 10-bit HEVC 的 mp4，我们请求了 mov 格式，方便剪辑软件和 ffmpeg 处理。
- **草稿（样片）模式**：请求里设 `draft=true`，只能是 480p，按 480p 计费；满意后用草稿任务 id（`draft_task`）再发一次请求生成正式版，当时只支持 1080p，按 1080p 计费，提示词和素材自动沿用，不要重复传。**草稿 id 有效期 7 天**。
- **计费公式**（按 token）：

  token ≈（输出秒数 + 输入参考视频秒数）× 输出宽 × 输出高 × 24 ÷ 1024

  2026-10 价目（元 / 百万 token）：

  | 输出 | 输入不含视频 | 输入含参考视频 |
  |---|---|---|
  | 480p | 70 | 42 |
  | 1080p | 77 | 46 |

  按此估算：5 秒首尾帧，480p 约 3.4 元，1080p 约 18.7 元；15 秒长镜头配 15 秒参考视频，480p 约 12.1 元，1080p 约 67 元。用实际 token 日志核对，不要只看价目表（曾把 1080p 单价误当成 480p 单价）。
- **人脸**：官方文档写明不支持直接上传含真人人脸的参考图或视频。实际中，图像模型画的写实脸也会被拒。当时唯一可信的人脸来源是**同一账号**在同平台图像模型（Seedream）生成的原图，用原始链接传，不裁剪、不重新编码。平台另有"含肖像视频"的官方方案，以文档为准。
- **参考视频只能用链接**（或平台素材 ID），不能用 base64。用对象存储的预签名链接（带有效期的临时下载地址）时：当时控制台默认有效期 1 小时，**把过期时间当成硬截止**，能设长就设长；草稿升级时平台可能会重新读取输入（未核实），升级前确认链接仍有效或准备重新签名。
- **上传限制**：图片每边 300–6000 px，宽高比 0.4–2.5，单张小于 30 MB；请求体不超过 64 MB（大文件不要用 base64）；参考视频 mp4 / mov，总像素 407,696–8,295,044，单个不超过 200 MB，帧率 24–60。另外，上传渠道本身也有限制（当时浏览器自动化工具上传单文件上限约 10 MB），超了就降码率、不降分辨率。
- **结果保存**：视频链接保存 24 小时、最多下载 100 次；任务记录保存 7 天。有每分钟请求数和并发数限流（429）。
- **商用**：用企业 API 和经过认证的账号，不用消费级 App；开通服务、签协议、付款都由用户本人操作。
- **API 账号还是 App 会员**：用户说"有 Seedance 账号"时先问清是哪一种。火山方舟 / BytePlus ModelArk 的 API 账号有密钥，附带客户端能用，有草稿升级；即梦、豆包这类网页和 App 会员没有 API 密钥，只能手动生成（`templates/prompts/video_pack_manual.md`），条款按消费级产品核对，草稿升级、清晰度档位和画幅选项以当时的页面为准，不要套用上面的 API 规则和价格。
- **海外用户**：字节跳动的国际站 BytePlus ModelArk 也提供 Seedance，模型 id、价格和币种不同，单独核对。附带客户端 `scripts/video_api/seedance.py` 用环境变量切换接口地址和模型 id。

### 其他视频模型（每条都要自己核对）

- **可灵 Kling（快手）**：有首尾帧和多图参考；核对当前版本的时长档位、首尾帧在哪些版本可用、有无低价预览档、人脸和商用条款。
- **Runway**：图生视频和视频编辑类模型；核对首尾帧支持、积分计价、商用条款。
- **Veo（Google）**：较新版本提供首尾帧和参考图能力；核对地区可用性、价格、输出水印。
- **海螺 Hailuo（MiniMax）**：有首尾帧和主体参考；核对分辨率、时长和价格。
- **换模型时**：先挑 3 个代表镜头（一条首尾帧产品镜头、一条有人物的长镜头、一条有效果的镜头），在每个候选模型上各出一条最便宜的预览，对比之后再定。
