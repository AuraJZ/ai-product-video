## 1. 3D 在这条流水线里管什么

**3D 只负责定位，它渲出来的像素不进成片。** 具体锁定这几样：

| 锁定项 | 说明 |
|---|---|
| 机位 | 相机位置、朝向、焦段、景深，以及镜头里的运动轨迹 |
| 布局 | 产品、家具、道具在画面里的位置和遮挡关系 |
| 比例 | 产品和周围物体的真实尺寸关系，接口、按键、字样的位置 |
| 走位（blocking） | 人物在什么时间走到哪里、身体朝向哪边 |
| 效果时间 | 灯什么时候亮、亮到哪里、气体或光扩散到多大范围 |
| 线缆与连接件 | 从哪里引出、贴着什么表面走、从哪里接入 |

最终画面的质感由图像模型（画关键帧）和视频模型（让画面动起来）完成。原因有两个：

- 纯 3D 的像素看起来就是 CG，即使材质调得很好，观众也能感觉到"假"。
- 视频模型会照抄它看到的每一个像素。给它 CG 画面，它就生成 CG 风格的视频。

每个镜头都要回答一句："**最终像素从哪来？**" 把答案写进镜头表的 `pixel_source`。默认只有两种答案："图像模型画的关键帧 + 视频模型"（`keyframe_video`），或者"文字卡 / 图形，由剪辑层生成"（`edit_layer`）；实拍和真实界面录屏是 `footage`。

> 案例：某产品片最初定的是"产品像素只来自 3D 渲染，AI 只画环境和人物"。第一批草稿一股 CG 味，被否掉。改成"3D 只出定位底图、所有像素由模型画"之后，质感才达标。

**按镜头的例外：要看清内部几何的技术镜头可以直接用 CAD 渲染。** 爆炸图、剖视图、机构怎么动（齿轮、刀盘、阀门、导轨）这类镜头，观众要看的就是真实的零件和它们的位置。交给图像模型重画，它会把零件"画得更合理"，编出不存在的结构；直接渲染又会有 CG 味。按镜头取舍：

| 镜头 | 像素来源 | 理由 |
|---|---|---|
| 外观、使用场景、人物、氛围 | 关键帧 + 视频模型（默认） | 质感最重要，外观已由底图和母版锁住 |
| 爆炸图、剖视、内部机构动作 | CAD / 3D 直接渲染（`cad_render`，镜头表 `mode: footage`） | 几何必须真；CG 味可以接受，甚至是"技术图"的语言 |
| 介于两者之间（外观特写里露一点内部） | 先试关键帧 + 视频；内部被画走样就改成渲染，或换一个不露内部的机位 | 用 Gate K 和逐帧看判断 |

直接渲染的镜头照样做第 9 节的耗时基准、照样降噪，灯光和色调尽量贴近 AI 镜头（同一张 HDRI 或同样的光位），并用剪辑转场（叠化、黑场）而不是 AI 过渡镜头接进去。这类镜头一般只进内部版（`09-compliance.md` 第 7 节），镜头表的 `audience` 写 `internal`。用户要求整片纯 CG，就是另一条流水线，先做第 9 节的渲染耗时基准再承诺。

## 2. 先判断：这支片要不要 3D

3D 能保证一致性，但要花建模时间。按下面的表判断：

| 情况 | 建议 |
|---|---|
| 产品外观必须精确（接口方向、字样、按键位置），而且同一产品在 5 个以上镜头里从不同角度出现 | 用 3D |
| 需要爆炸图、剖视图或引线标注，标注要对准具体部件 | 用 3D（锚点要从 3D 坐标投影，见 06） |
| 有人物和产品互动、走位、一镜到底的长镜头 | 用 3D（至少用简易几何做走位） |
| 效果有严格的先后顺序或空间范围 | 用 3D |
| 已经有 CAD 或现成的 3D 模型 | 用 3D，成本很低 |
| 15 秒以内的社交广告，产品只在 1–2 个镜头里出现 | 可以不用，走第 10 节 |
| 镜头以氛围和人物为主，产品是静物、只有轻微运镜 | 可以不用 |
| 团队没有 3D 能力，时间又很紧 | 走第 10 节，但收紧产品检查 |

中间路线：**简易几何也算 3D**。几个盒子和圆柱按真实尺寸摆好，就能定机位和比例，不需要精模。产品外观的"真相"再由产品参考图（第 10 节）提供。

## 3. 单一母版资产

产品只建一次，所有镜头共用它。这样"产品外观一致"由代码保证，而不是靠人记。

1. **规格文件是唯一来源**。尺寸、颜色、材质、字样内容和位置、接口位置、线缆规格，只写在一个文件里（比如 `spec.py` 或 `spec.json`）。建模脚本只从这里读数，镜头里需要的数值（光圈半径、效果范围、机位距离）也从这里算。规格来自已确认的产品事实单（见 `01-intake.md`）。
2. **母版文件**。由脚本按规格生成一个母版场景文件（比如 `master.<3D 软件的场景格式>`）。
3. **镜头链接母版，不复制**。每个镜头文件以"链接"方式引用母版里的产品。镜头里只允许改白名单里的属性，比如指示灯颜色、效果强度、开关状态。
4. **一致性检查**。写一个脚本扫描所有镜头文件，确认没有哪个镜头私存了产品副本或改了白名单之外的属性。通过时打印 `CONSISTENCY PASS`。
5. **多视角审阅图**。固定 6 个视角（正、背、左、右、顶、3/4）渲成一张拼图，和品牌图、实物照片并排给用户看。外观改到用户签字确认后，再做效果和镜头。外观问题在这一步改最便宜。

### 3.1 从 CAD 开始

产品方有 CAD 时，母版从 CAD 导入，而不是照图重建。几件事第一天问清：

1. **要什么格式**：请产品方从 CAD 软件导出 STEP（.step / .stp）和一份网格格式（FBX、OBJ 或 glTF），**单位毫米**，外观件和内部件分开（或按装配树保留层级）。很多 3D 软件不能直接读 STEP，要先用 CAD 软件或开源的 CAD 工具转成网格（工具见第 12 节）；转的时候设好弦高 / 角度公差，曲面才不会一棱一棱的。
2. **冻结一个版本**：CAD 一直在改。选定一个版本号（文件名 + 日期 + 修订号），写进 `brief/product_facts.md`，之后的底图、关键帧都按它；产品方再改，按"事实更正"走（上面的清单）。
3. **核对尺寸和朝向**：导入后量总高、总宽、关键孔位，和事实单逐项比；单位错（米 / 厘米 / 毫米）会差 10 倍、1000 倍。确认哪一面是正面、字样朝向、坐标轴向上方向。
4. **减面**：CAD 网格动辄几百万面，底图用不着。外观件按画面里的最大尺寸减面，内部件只在要露出来的镜头里保留细节。
5. **材质和颜色（CMF）**：CAD 里一般没有可用的材质。按产品方的 CMF 表（颜色、材质、表面处理）给每个零件指定材质：底图只要颜色和明暗对，统一用干净的漫反射 + 适度高光，质感交给图像模型；颜色值和色卡写进规格文件。
6. **内部件分组**：外观件、内部件、紧固件、线缆各放一个集合（collection / layer）。外观镜头隐藏内部件；爆炸图、剖视按集合控制位移和剖切平面（剖切用布尔或剖切平面，切口给一个统一的截面颜色）。这些镜头按第 1 节的例外处理，一般只进内部版。
7. **保密**：CAD 文件、内部件渲染不进任何公开渠道，也不上传给图像、视频模型的消费级入口；内部件只在本机和内部版里用。

**事实一旦更正**（尺寸、朝向、出口位置……）：

- 立刻停掉所有正在按旧规格跑的渲染，旧规格渲出的每一帧都是浪费；
- 改规格文件 → 重建母版 → 重渲受影响的底图；
- 同时检查下游：关键帧提示词、视频提示词、标注、字幕、brief 里有没有旧说法，改完全局搜一遍残留词。

## 4. 镜头表与"事实底稿"

**镜头表是全片时间轴的唯一来源**（模板 `templates/shot_list.json`，复制成项目的 `shots/shot_list.json`）。每个镜头一行：镜头 id、时长、机位随时间的关键点、效果缓动曲线、人物姿态时间点、像素来源、用哪种生成模式（见 05）。剪辑、提示词、音效都以它为准。

**事实底稿**：写一个不依赖 3D 软件界面的小脚本，每 0.5 秒导出一次：

- 相机位置、目标点、焦段、景别；
- 哪些地标（产品正面、接口、字样、人物头部）在画面里，像素坐标是多少；
- 每个效果的数值（亮度、颜色、范围）；
- 人物姿态（站、坐、躺、手的位置）。

逐秒提示词里的机位、速度、效果时间都从这份底稿复制，不手写。手写的时间很容易和参考视频对不上，模型会把效果顺序生成反。

**运镜要省着用**：

- 每个镜头只用一种慢速、单方向的运动，并写成数字：环绕不超过 15°，推拉不超过 10%，平移每秒约为画面宽度的 2%。
- 每 4–5 秒只安排一个动作高峰，前后保持平稳。
- 运动途中不要露出首帧和尾帧里都没有的东西（产品背面、线缆尽头、房间另一侧）。首尾帧模式只锁两端，中途新露出来的部分由模型自己编，多半是错的。非露不可时，给那一刻画一张中间关键帧，用有序关键帧模式生成（`05-video-gen.md` 第 1 节）。

## 5. 底图契约（plate contract）

"契约"是指 3D、出图包、自动检查和视频请求四方共用的一套固定文件格式。每张关键帧一个文件夹：

```
plates/<keyframe_id>/
  plate.png         # exact keyframe camera, effects in this keyframe's state, denoised
  plate_fxoff.png   # same frame, all effects off: shows what the painter changed
  plate_clean.png   # same frame without the stand-in (only when a person is present)
  mask_product.png  # 8-bit, 255 = pixels of this object visible from this camera
  mask_<part>.png   # one mask per product / part / cable, occlusion respected
  sidecar.json      # camera, landmarks, boxes, cable path, effect values
```

`sidecar.json` 示例（字段可按产品增减）：

```json
{
  "id": "S05-K00", "shot": "S05", "t": 0.0, "size": [2048, 1152],
  "camera": {"loc": [0.42, -1.10, 0.95], "target": [0.0, 0.0, 0.55], "lens": 35, "sensor": 36},
  "landmarks_px": {"product_front": [[910, 402], [1130, 402], [1130, 610], [910, 610]],
                   "port": [1188, 590], "lettering": [1020, 575], "head": null},
  "bbox_px": {"product": [880, 380, 1210, 640]},
  "cable_polyline_px": [[1188, 590], [1260, 640], [1500, 700]],
  "fx": {"indicator_on": true, "indicator_color": "amber", "glow_radius": 0.0},
  "person": "none"
}
```

每样东西的用途：

| 文件 | 给谁用 |
|---|---|
| `plate.png` | 关键帧出图包的"图1"，图像模型照它的构图和比例画 |
| `plate_fxoff.png` | 自动检查对比"效果开没开"、颜色有没有变 |
| 遮罩 | 自动检查（Gate K）比对产品轮廓、比例、线缆，见 04 |
| `sidecar.json` | 引线标注锚点投影（06）、画偏后的配准救图（04）、地标位置检查 |

底图参数：

- 分辨率略高于输出（比如输出 1920×1080，底图 2048×1152，同为 16:9），画幅比例和成片完全一致；
- 足够的采样加降噪，**不能有噪点、锯齿、粗网格**，这些会被图像模型画成"砂纸""浮石"一样的质感；
- 效果的颜色在底图里就定对。底图里偏粉的灯，画出来也会偏粉；
- 给用户发一张底图总览拼图，标好编号。

## 6. 灰模视频（clay video）

只有镜头内部的**时间或方向**很重要时才做：人物走位、效果有先后、10 秒以上的一镜到底。它告诉视频模型"机位怎么走、人在什么时候到哪、效果什么时候发生"，不提供任何长相。

- 全部材质统一为中性灰；只保留必须表达时间的那个效果（比如指示灯亮起）；
- 足够采样并降噪，不能有噪点和闪烁；
- 人物用替身（第 7 节）；
- 时长和成片镜头一致，帧率和输出一致（常见 24 fps）；
- 上传前压到平台大小限制以内：**降码率，不降分辨率**；
- 先拼一张联系表（一张图排满多帧）看一遍，确认替身没有挡住镜头、没有穿模。

> 案例：某产品片第一次用的参考视频是低采样预览，模型生成的画面和预览的相关度高达 0.91–0.98，预览里的噪点变成了砂纸一样的家具和石头一样的产品。改成降噪后的统一灰模，再把质感全部放进关键帧，问题才消失。

## 7. 替身（stand-in）

- **只做躯干加头**，用真实身高，中性灰，不用彩色。方块四肢的替身会把僵硬的动作"教"给模型。
- 不和道具穿插。
- **脸转开**：头部朝向镜头的反方向。底图里的替身头可以加一块深色"头发"和一只灰色耳朵，让图像模型一看就画成后脑勺，而不是自己编一张脸。
- 手、脚、重心、布料怎么动，写在视频提示词里（见 05）。替身只提供时间。
- 底图里替身的头通常比真人大，**字幕位置要在真实草稿上复查**（见 06）。

> 案例：某产品片的方块替身让人物在 0.17 秒内从站着变成坐下，接下来的动作里身体扭转 90°。换成躯干加头的替身，并把"手撑、挪身、前臂支撑、抬腿、头落下"逐项写进提示词后才自然。

## 8. 从每个真实机位检查

生成之前，从**每一个真实机位**（不只是俯视图）把 3D 场景对照书面产品事实检查一遍。底图是画师眼里的"产品真相"，错误会传到之后的每一次生成。

- [ ] 产品朝向对吗？正面、字样、接口是否朝着该朝的方向？
- [ ] 线缆从正确的接口引出，贴着表面走，不悬空、不打急弯、不穿进任何物体？（做一次碰撞检查，留几毫米间隙）
- [ ] 每个效果都从真实的来源出发，并且被限制在它所属的表面和范围内（裁到表面边界、高度封顶）？
- [ ] 效果有没有暗示产品没有的机理？画面里有雾，观众就会以为产品能喷雾；画面里有光，观众就会以为那里有灯。
- [ ] 关键帧描述在这个机位下真的拍得到吗？把描述里的地标投影到画面上验证。
- [ ] 镜头运动途中会不会露出首尾帧里没有的东西？
- [ ] 产品和参照物（手、杯子、家具）的比例对吗？

重新渲染之前，先确认渲染程序**实际从哪个文件读参数**。参数常常有两份来源（镜头表和关键帧清单），改错了地方，一次渲染就白跑。缓存遇到输入变化不能悄悄跳过，要有强制重渲的开关。

> 案例：某产品片的设备在场景里被转了 −90°，正面朝着画面里的人，于是正面和字样在所有镜头里都拍不到，插头反而朝着镜头。另一处线缆在家具边角像发夹一样扎进布面。这些都是从实际机位看才发现的。

## 9. 渲染耗时基准

承诺任何排期之前，在**用户自己的机器**上测真实耗时：

1. 每类场景（普通、有体积光或雾、特写）各渲一帧，用最终画质设置；
2. 不算第一帧（第一帧包含着色器编译时间）；
3. 单帧耗时 × 总帧数 = 纯 3D 方案的总时长。体积雾、体积光通常让耗时翻 2–3 倍。

> 案例：在一台没有独立显卡的笔记本上，单帧实测 75–190 秒，85 秒的片要渲 60–70 小时。改成"3D 只出几十张底图和几段灰模视频"之后，渲染只要几个小时。

机器偏弱时的规则：

- 一次只开一个渲染进程，有日志、能续跑，失败自动重试最多 3 次；
- 长渲染放在后台跑，用监视工具看日志或文件修改时间，完成或出错时通知；
- 无人值守之前，请用户插上电源，并**由用户自己**把系统睡眠设为"从不"；
- CPU 先让给挡住下一步付费生成的任务。

## 10. 没有 3D 模型时怎么做

没有 3D 模型也能走这条流水线，但要用更严格的产品检查来补偿。

### 10.1 用产品参考表代替 3D 母版

做一张**产品参考表**：中性灰背景上，同一比例的正、侧、背、顶、3/4 视图，加上接口、字样、按键的特写。来源按可靠程度排：

1. 实物照片抠图（最可靠，光线要均匀、无强反光）；
2. CAD 渲染图；
3. 图像模型根据实物照片生成的参考表——**每一张都要和实物逐项核对**，再请创始人确认。

这张参考表就是"产品真相"，每张关键帧都上传它。

**没有照片、没有渲染图（只有概念）时**：产品还没有样品，也没有任何渲染，"产品真相"就只能由我们一笔一笔定下来，不能交给图像模型去猜。

1. **收集能拿到的一切**：创始人的草图（手绘拍照也行）、文字规格（尺寸、形状、颜色、材质、接口和按键位置、字样）、参考的同类产品（只用来说明"像哪种做法"，不能照抄外观）。
2. **先做几何**：按规格用最简单的几何体（盒子、圆柱、倒角）搭一个真实尺寸的模型，或者用纸盒、泡沫按尺寸做一个手板，用手机从固定视角拍下来。比例、开孔位置在这一步定。
3. **再上表面**：以这些几何图为图1，让图像模型按文字规格画出参考表的各个视角（正、侧、背、顶、3/4 和细节特写），一次一个视角，不让它自己补没写的细节。
4. **逐个视角请创始人签字**：每个视角确认"就是这样"之后才进参考表；改了就重画那一张。签字记进 `brief/decisions.md`。
5. **之后每张关键帧都按 REVIEW 处理**：没有实物可比，Gate K 只能比轮廓和比例，外观细节每张都由创始人过目；片尾和简介说明"产品为概念设计 / 视觉示意"（`09-compliance.md` 第 2.2 节）。

### 10.2 用 2D 底图代替 3D 底图

- **俯视调度草图**：每个镜头画一张平面图，标出相机位置和焦段、产品位置、人物路线。只给自己和用户看，**不要**上传给视频模型（带标注的图会被照抄）。
- **2D 合成底图**：把抠好的产品照片按正确比例贴到房间照片或图像模型生成的房间图上，透视对齐，作为"图1"。
- **实拍代理**：用和产品同尺寸的纸盒或旧设备，摆在真实的桌面或房间里，用手机按设想的机位拍一张。这就是最便宜的底图，比例和透视都是真的。

### 10.3 更严格的产品检查

没有 3D 遮罩和坐标，检查要靠人工补：

- 遮罩用分割工具在 2D 底图上抠出，再人工修边；
- 每张关键帧都对照参考表查：轮廓、长宽比、接口和字样的位置、产品数量；
- 字样逐张人工看，放大到 100%；
- 运镜更保守：优先固定机位或轻推，不做会露出产品另一面的环绕；
- 镜头更短（4–5 秒），少用手近距离操作产品（手指和产品细节最容易一起漂移）；
- 引线标注的锚点在批准的画面上手工量（见 06）。

### 10.4 什么时候值得补做 3D

出现下面任一情况，就停下来补一个简易 3D（盒子加圆柱也行）：

- 有 3 个以上镜头因为产品走样被退回两次；
- 需要爆炸图、剖视图或多部件标注；
- 同一产品要在很多机位里保持一致的比例；
- 有一镜到底的长镜头或人物走位。

## 11. 竖屏 9:16 的构图

**画幅在第一天就要定。** 竖屏不是横屏裁出来的。

| 情况 | 做法 |
|---|---|
| 主要投放在竖屏平台（短视频信息流） | 3D 相机直接按 9:16 设置，底图 1152×2048，关键帧和视频都按竖屏生成 |
| 横竖都要 | 英雄镜头分别出横、竖两套底图（默认）；次要镜头可以从横屏裁，但横屏构图时就要保证中间那一条竖向区域装得下产品和动作，或者源素材是 4K（`02-formats.md` 第 8.3 节） |
| 只做横屏 | 照常 |

从 1920×1080 裁 9:16，只剩中间约 608 像素宽，放大后清晰度明显下降，很多镜头的产品或人物会被裁掉一半。所以横屏构图时要提前看"竖屏安全区"：给每个 3D 相机同时显示两个取景框（16:9 全画面和它中间的 9:16 竖条），渲一张带两个框的底图总览，逐个确认产品和动作在两个框里都完整。

竖屏构图要点：

- 产品放在画面中上部，大一些；
- 产品关键部位和字幕都放进竖屏保守安全框：上留 15%、下留 35%、左留 6%、右留 10%（1080×1920 上约 x 65–888、y 288–1248），框外会被平台按钮和文案遮挡；数值和出处见 `02-formats.md` 第 5、9 节，投放前再用平台官方模板核对；
- 竖向运动（升降、上下摇）比横向平移更适合竖屏；
- 多用近景和特写，少用全景；
- 很多视频模型的输出画幅跟随首帧，**关键帧的画幅决定了视频的画幅**，竖屏片的关键帧必须是竖的。

## 12. 工具备注（2026-10，使用前核对最新文档）

方法本身和工具无关。以下是当时用过或常见的选择，版本和功能变化很快，用之前查一遍官方文档：

- **Blender**：免费，能用 Python 脚本完整控制（建模、链接母版、渲染、导出相机参数），适合"一切写成代码"。出底图可以用实时渲染引擎（EEVEE）加降噪，速度快；遮罩可以用物体索引通道或单独的视图层渲出。便携版不需要安装。
- **其他 3D 软件**：Cinema 4D、Unreal Engine、Unity 都能做预演；KeyShot 之类的产品渲染软件适合做产品参考表，但不适合做走位。
- **没有 3D 时**：抠图和分割可以用开源的背景去除或分割模型；实拍代理只需要一部手机。
- **CAD 转换**：STEP 转网格可以在产品方自己的 CAD 软件里导出，或用开源的 FreeCAD；Blender 当时不能直接导入 STEP（有第三方插件），导入 FBX / OBJ / glTF 时把单位设成毫米再核对尺寸。
