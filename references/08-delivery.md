## 1. 交付什么

| 文件 | 用途 | 说明 |
|---|---|---|
| 放映母版 | 路演投屏、官网、上传平台的源文件 | 高质量，体积大；告诉用户放在哪个文件夹 |
| 分享版 | 聊天软件转发、手机上看 | 按发送渠道的大小上限压缩；直接把文件发给用户 |
| 各画幅版本 | 16:9、9:16、1:1、4:5（按投放需要） | 第 3、4 节 |
| 无字版（textless） | 以后做新语言、新广告时复用 | 同一条 EDL 关掉字幕和标注即可出 |
| 音频分轨 | 音乐、音效、旁白分开的 wav | 给代理商或以后重混 |
| 字幕文本 | 平台的隐藏字幕（CC）、无障碍 | 从字幕数据导出 SRT |
| 封面图 | 平台封面、文章配图 | 从生成原片里挑干净的帧，不用带字幕的成片帧 |
| 授权与说明 | 音乐、音效、字体的许可证；AI 生成说明；版本记录 | 一个文本文件，许可证部分从 `brief/licenses.md` 导出 |

所有交付文件放在项目的 `deliver/` 里，公开版和内部版分两个子文件夹（例如 `deliver/public/`、`deliver/internal/`）。文件命名按 `02-formats.md` 第 8.5 节：`<project>_<type>_<aspect>_<seconds>s_<lang>_v<nn>.mp4`，比如 `deskLamp_explainer_16x9_90s_zh_v02.mp4`；分享版在末尾加 `_share`。

## 2. 编码参数

ffmpeg 可以从 `imageio-ffmpeg` 取：

```bash
uv run --with imageio-ffmpeg python -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())"
```

**放映母版**（H.264，画质优先）：

```bash
ffmpeg -i picture.mov -i mix.wav -map 0:v -map 1:a \
  -c:v libx264 -preset slow -crf 18 -profile:v high -pix_fmt yuv420p \
  -c:a aac -b:a 256k -ar 48000 -movflags +faststart master.mp4
```

CRF 是画质参数，越小越清晰、文件越大；18 基本看不出损失。`yuv420p` 和 `+faststart` 保证手机、浏览器、聊天软件都能直接播放。

**分享版**（按大小上限算码率）：

视频码率（kbps）≈ 目标大小（MB）× 8192 ÷ 时长（秒）− 音频码率（kbps），再留 3–5% 余量。

例：上限 30 MiB、时长 111 秒、音频 160 kbps → 30 × 8192 ÷ 111 − 160 ≈ 2054 kbps，取 1950 kbps。用两遍编码（two-pass）控制大小：

```bash
ffmpeg -y -i master.mp4 -c:v libx264 -preset slow -b:v 1950k -pass 1 -an -f mp4 NUL      # use /dev/null on macOS / Linux
ffmpeg -i master.mp4 -c:v libx264 -preset slow -b:v 1950k -pass 2 -pix_fmt yuv420p \
  -c:a aac -b:a 160k -movflags +faststart share.mp4
```

不需要精确卡大小时，用 CRF 24、AAC 160k 通常就够了。先问清发送渠道的上限（不同聊天软件、邮箱、远程发送工具各不相同）。

**给代理商或媒体投放**：另出一份高码率中间格式（比如 ProRes 422 HQ，或 H.264 高码率），加音频分轨，按对方的交付规范来。

**帧率**保持源素材的帧率（很多视频模型输出 24 fps），不要随手转成 30 fps，除非平台或对方明确要求。

## 3. 各平台的画幅和规格

| 画幅 | 分辨率 | 常见去处 | 注意 |
|---|---|---|---|
| 16:9 横屏 | 1920×1080 | 官网、长视频平台、路演投屏 | 默认母版 |
| 9:16 竖屏 | 1080×1920 | 短视频平台、Stories、Reels、Shorts | 底部和右侧有平台界面遮挡 |
| 1:1 方形 | 1080×1080 | 信息流 | 横屏素材左右各裁掉约 22% |
| 4:5 竖向 | 1080×1350 | 图文信息流、部分社交平台 | 比 1:1 多一点高度 |

**竖屏安全区**：短视频平台会在画面上叠加账号名、文案、点赞和评论按钮。本 skill 用 `02-formats.md` 第 5 节的保守安全框：上留 15%、下留 35%、左留 6%、右留 10%（1080×1920 上约 x 65–888、y 288–1248），字幕、标志、CTA 和产品关键部位都放进框里；各平台的数值和出处见该文件第 9 节。界面经常改版，**投放前按平台当前公布的安全区模板核对**，把模板叠在成片上看一遍。附带剪辑器用样式预设 `"preset": "feed_safe"` 把竖屏的字幕、角标和片尾小字放进这个框，`--dry` 逐条检查；竖版的 EDL 写 `"size": [1080, 1920]`（见 06 第 1、5 节）。

**常见时长**：广告 6 秒（不可跳过的短广告）、15 秒、30 秒；产品演示片（含投资人片）60–120 秒。各格式的结构见 `02-formats.md`。

**AI 内容标识**：每个画幅版本都保留开头画面的 AI 标识（至少约 2 秒，竖屏放进安全框）和片尾说明；上传时按平台要求勾选"AI 生成内容"声明（各平台做法见 `09-compliance.md` 第 4.3 节）。不挂常驻角标，除非平台要求。

## 4. 换画幅：重新构图，不是简单裁切

| 做法 | 什么时候用 | 质量 |
|---|---|---|
| A. 原生生成：底图、关键帧、视频都按目标画幅重新出 | 英雄镜头（钩子、产品亮相、片尾产品镜头）的默认做法；产品特写 | 最好 |
| B. 按镜头重新取景裁切：每个镜头单独决定裁哪一块，必要时让裁切框跟着主体慢慢移动 | 只用于次要镜头，而且横屏构图时已经给竖条留了位置（见 03 第 11 节），或源素材是 4K（`02-formats.md` 第 8.3 节） | 好 |
| C. 背景填充：竖屏上下用模糊放大的同一画面填满 | 时间紧、次要渠道 | 一般，看得出是"转出来的" |
| D. 用图像模型往外扩画面，再重新生成视频 | 少数关键镜头 | 不稳定，产品细节要重新检查 |

字幕和标注**不能跟着画面一起缩放**：每个画幅单独一条 EDL，字幕位置重新打分（见 06 第 6 节），引线标注重新排版。

## 5. 剪短版（cut-down）

从长片剪出 30 秒、15 秒、6 秒版本：

1. **重写，不是截断**。每个短版都要有完整的结构：
   - 广告：前 1–2 秒就是钩子（产品本身或它解决的问题），中间一个信息点，结尾品牌和行动号召；
   - 解说片的短版：只讲一两个最强的功能。
2. 复用同一批批准片段，写一条新的 EDL。
3. **音乐重新剪**：在乐句或小节处切，结尾落在一个完整的终止上（见 07），不要硬切或半句淡出。
4. 字幕重新算阅读时间；短版里删掉的功能，对应的字幕和标注也删干净。
5. 每个短版的每一句都重新过合规检查。
6. 每个版本单独测响度。

## 6. 发送前检查

每个要发出去的文件都过一遍：

- [ ] 时长和预期一致；
- [ ] 有一条视频流、一条音频流；编码、像素格式（`yuv420p`）、分辨率、画幅、帧率都对；
- [ ] 整体响度和真峰值达标（见 07 第 9 节）；
- [ ] 截帧检查：第一帧、片头卡、每条字幕的中间时刻抽几张、最后一帧；
- [ ] 没有残留的草稿角标（比如"草稿"标记）或占位标牌；
- [ ] 开头画面有 AI 标识（至少约 2 秒），片尾有 AI 说明和音乐署名，没有常驻角标（平台要求的除外）（`09-compliance.md` 第 4.2 节）；
- [ ] 文件大小符合发送渠道的上限；
- [ ] 在手机上（iOS 和 Android 各一台更好）、在常用聊天软件里能直接播放；
- [ ] 文件名符合约定，版本记录写好。

查看流信息和测响度（`imageio-ffmpeg` 只带 ffmpeg，不带 ffprobe，用 ffmpeg 本身就够了）：

```bash
ffmpeg -hide_banner -i final.mp4                                     # streams, duration, codec, size
ffmpeg -hide_banner -i final.mp4 -af ebur128=peak=true -f null -      # integrated loudness and true peak
ffmpeg -ss 12.5 -i final.mp4 -frames:v 1 check_12.5s.png              # grab one frame at 12.5 s
```

交付时：分享版直接发文件到用户手机；母版太大时告诉用户完整的文件夹路径。

## 7. 交付之后的小改

用户最常问："要全部推翻重来吗？"多数情况下不用：

- **改片头、改某条字幕**：分段缓存只重渲改动的那一段，再把原来的混音原样合回去（音频 `-c:a copy`）。卡片时长不变，音乐和音效就不用动，也不产生生成费用。
- **只改混音**：画面流直接复制，只重做音频：

  ```bash
  ffmpeg -i picture_final.mp4 -i mix_v2.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 256k -movflags +faststart master_v2.mp4
  ```

- **换一个镜头**：生成、审批、更新账本（`edit/approved_drafts.json`），重跑 EDL；镜头时长变了，就重跑字幕间隔检查和声音脚本。

回答时先给结论（"不用推翻，改这几处，约 N 分钟"），再讲理由，最后列出需要用户确认的点。

## 8. 多语言版本

**画面、剪辑节奏、音乐都不动，只换屏幕上的文字**（有旁白的再换旁白）。没有旁白的片子，音轨直接复用。

### 8.1 一份文案文件 → 平行的数据文件

1. 把所有上屏文字（字幕、标注、卡片，包括开头的 AI 标识和片尾说明）按 id 列进一份文案文件，比如 `edit/copy_en.json`：

   ```json
   {"S07": {"main": "Soft light, right where you read", "emph": ["Soft light"], "max_px": 820},
    "callout.S03.2": {"name": "Dimmer dial", "func": "Turn for brighter or softer light", "max_px": [302, 302]}}
   ```

2. 一个生成脚本（放在 `work/`）读它，写出平行的字幕、标注和 EDL 文件（比如 `edit/captions_en.json`、`edit/callouts_en.json`、`edit/edl_en.json`）：**时间和位置都与原版相同**，只换文字和该语言的样式（字体、字号、字距）。
3. 每种语言一套样式预设（附带剪辑器有拉丁文预设，见 06 第 5 节）。

### 8.2 渲染器只加开关，默认值不变

- 为新语言加的每个开关，**默认值都等于原来的行为**；
- 改代码前备份旧的渲染器；
- **像素回归**：用新旧两套代码，把原语言的全部字幕、卡片、标注各渲一遍，逐像素比对，必须是 0 处不同。这能证明原版没有被改动。

> 案例：某产品片做英文版时，把中文的 28 个文字输出用新旧代码各渲一遍比对，0 处不同；扫描时间线，残留中文字符 0 个。

### 8.3 按像素给文案定长度上限

溢出是像素问题，不是字数问题：

1. 对每条字幕和标注，算出可用宽度：画面宽度 − 安全边距 − 引线间隙 − 锚点那一侧占用的宽度；
2. 用选定的字体和字号实测平均字宽（Pillow 可以量），换算成字符上限；
3. 把"每条最多多少像素 / 多少字符"作为硬性要求交给文案；
4. 渲染后按**实际像素宽度**检查。按中文字数写的规则（比如"一行不超过 12 个字"）对拉丁文无效，它报出的警告是误报，过滤掉。

### 8.4 多人起草的文案流程

1. **三路并行起草**：三个写手（可以是三个 agent）从不同角度各写一稿，比如清晰、克制、有温度；
2. **评审逐条合并**：每一行选最好的，或者组合；
3. **合规检查 + 母语检查**分开做：直译常常生出新的宣称（比如把"摸起来是温的"译成暗示身体效果的说法），或者变成绝对化表述（"non-slip"要改成"slip-resistant"）；
4. **修订定稿**，再做一次独立终检；
5. 每一行都带上 id、像素上限和"画面上此刻是什么"的说明，写手才能写对。

### 8.5 渲染后检查

- **残留原语言扫描**：用正则匹配时间线里的每一条文字。目标是英文等拉丁文版本时，扫中文字符和全角标点：

  ```python
  import re
  CJK = re.compile(r"[㐀-䶿一-鿿豈-﫿　-〿＀-￯]")
  ```

  结果必须是 0 命中。
- **按每条字幕的中间时刻截帧抽查**，在原尺寸裁切图上看字号：细的拉丁大写字母看起来比同像素的中文小，常常需要加大 1–2 px。
- 开头的 AI 标识和片尾卡的 AI 说明都换成目标语言，并符合目标市场的规定；音乐署名不变。
- 从右往左书写的文字（阿拉伯文、希伯来文）和需要字形组合的文字（泰文、印地文）需要支持复杂排版的渲染（比如带 raqm 的 Pillow），先出一张静帧验证。
- 有旁白的语言版本：新旁白比原来长时，要么改写旁白，要么调整剪辑，然后重跑字幕间隔和声音检查。

## 9. 公开传播版

给投资人看的版本可以讲内部结构；**公开发布的版本**（社交平台、公众号、公开演讲）不放爆炸图、剖视图和能看出内部结构的镜头，也不写内部部件名称和工作原理，只用外观、氛围、人物和使用场景。在剪辑层另开一条 EDL 出这个版本，不重新生成画面；封面和配图从生成原片里选干净的帧。细则见 `09-compliance.md` 第 7 节。
