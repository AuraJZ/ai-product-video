# 07 声音：音乐、音效、旁白、混音

画面和声音分开做，最后合成。声音的文件（分轨、音效清单、时间窗、混音报告）都放在项目的 `sound/` 里。所有声音都从剪辑器写出的时间线（`renders/<EDL 名>_<宽>x<高>.timeline.json`）读时间，所以 1080p 升级、改字、调序都可以和声音制作同时进行。

## 1. 先定声音方案

| 方案 | 适合 | 信息由谁承担 |
|---|---|---|
| 音乐 + 音效，不配旁白 | 产品解说片、投资人演示、安静型产品、静音自动播放的信息流 | 字幕 |
| 音乐 + 音效 + 旁白 | 带口播的广告、需要讲清复杂流程的教程、无障碍版本 | 旁白，字幕补充关键词 |
| 只有音乐 | 6–15 秒的短广告、氛围片 | 字幕和画面 |

没有旁白的片子，换语言时音轨可以直接复用（见 08）。决定配旁白之前，先看第 7 节的质量要求：做不到"听不出是合成的"，宁可不配。

## 2. 音乐：选曲与授权

- **发 3–4 首能直接播放的音频文件**给用户选，不要只发网页链接或文字描述。用户没法从描述里听出音乐。
- **每首都记授权**：来源网址、作者、曲名、许可证类型、下载日期，保存许可证页面的截图或 PDF，记进 `brief/licenses.md`（模板 `templates/licenses.md`，规则见 `09-compliance.md` 第 5 节）。
- 常见许可证要注意的点：
  - **CC BY**：可以商用，但要按作者要求的格式署名；剪辑过的要注明"(edited)"。
  - **CC BY-NC**（非商业）：商业宣传片、广告不能用。
  - **CC0 / 公有领域**：最省心，仍然记下来源。
  - **曲库订阅或单曲授权**：确认授权范围是否包括广告投放、付费推广、线下活动；有的普通授权不覆盖付费广告，需要扩展授权。
- **AI 生成的音乐**：版权归属在很多地区仍不确定，平台条款也各不相同。默认不用；用户坚持使用时，确认生成服务明确授予商用权利，并告知风险。
- 需要注册账号才能下载的素材网站，由用户自己登录下载，Claude 不创建账号。

## 3. 音乐：按画面剪

- **先测量，再剪**：实测原曲的定音（A4 是不是 440 Hz）、调性、速度（有没有稳定的节拍）。粗略的自动估计工具常出错，和实测矛盾时以实测为准。
- **没有稳定节拍的音乐**（钢琴、氛围类）：剪点放在乐句的"换气"处，不按小节硬切。
- **节拍明确的音乐**（广告常用）：剪点卡在小节线或强拍上；画面的硬切也对齐节拍。
- **音乐的变化落在画面的变化上**：比如弦乐进入的那一刻，对准光照亮墙面的那一刻；最后一个乐句落在片尾卡上，结束在一个完整的终止上，不要半句淡出。
- 画面调序后，音乐的段落安排也要重新检查，脚本里不要写死旧的转场顺序。
- 音乐分轨先做到约 **−20 LUFS**，留给混音去平衡。

## 4. 音乐：跨段的和声衔接

两段音乐调性不同时，只靠"渐弱 → 静音 → 渐强"听起来仍然突兀。正确做法：

1. **分析和弦与低音**：算出两段随时间变化的和弦（色度特征）和低音走向。
2. **找共同的和弦**：在两段里找和弦相同、或共同音最多的位置作为接点。
3. **在共同和弦上做约 3 秒的等功率交叉淡化**，让原曲自己的和声进行把调性带过去。
4. **相位对齐**：两段共有的低频音在交叉时可能互相抵消。把后一段在 ±4 毫秒范围内、按 0.125 毫秒一步微调，取相关度最高的位置。
5. **拒绝"幽灵起音"**：交叉处多冒出 3 dB 以上的音头，就换一个接点。
6. **不要**先淡出、留一段静音、再淡入。
7. 每个接点导出一个 20 秒的试听 wav（接点前后各 10 秒），交给独立审查测一遍，再发给用户听。

> 案例：某产品片夜景段在一个大调、晨景段已经转到另一个调。第一版在熄灯后的静音里切换，用户说"切换太过度了""不能只按渐弱渐强来过渡，曲调上也要和谐"。改成在两段共有的大七和弦上做 3 秒交叉淡化，并对齐相位后，用户接受了这一版。

## 5. 音效：清单与"谁在动作"

**先写音效清单（cue sheet），再做声音。** 模板 `templates/sfx_cue_sheet.md`，复制成 `sound/sfx_cue_sheet.md`。 每个声音都是一个声明："谁在这一刻做了什么"。观众会从声音推断因果。

| 字段 | 示例 |
|---|---|
| id | `sfx_07` |
| 锚点 | `S07 +1.2`：镜头 S07 起点之后 1.2 秒（成片里的绝对时间由脚本从当前时间线算出，不手写） |
| 谁在动作 | 产品自动亮灯（不是人按开关） |
| 声音 | 很轻的上滑音，没有咔哒声 |
| 来源 | 本地合成，定在主音 |
| 电平 | 由音效报告给出 |
| 备注 | 和标注提示音错开 0.3 秒 |

规则：

- **自动发生的动作没有开关声**：产品自己亮灯或调暗，就不配手按开关的咔哒，否则观众以为是人按的开关。
- **因果顺序不能反**：产品的提示音之前，不要出现会被误认为是"触发源"的环境声。
- **安静型产品默认无声**，只放有用意的提示音。
- **环境声随场景一起结束**，不要留一层从中段一直响到结尾的底噪。
- **标注提示音要低而柔**：比如低沉的木槌音，频率取主音的 1.5 倍（五度），阻尼衰减，低通约 1.8 kHz，起音约 6 ms；声像往标注所在的一侧偏约 20%。明亮的界面"嘀嘀"声会显得尖。
- **广告片**可以有更明显的音效（转场的呼啸声、产品的"英雄"音），但同样遵守"谁在动作"。
- **按时间线放置**：音效脚本从 `timeline.json` 按"某镜头第几秒"读取时间，不写死镜头顺序。重剪之后重跑一次就能对齐。
- 每条音效的电平写进报告（比如 `sound/sfx_report.json`），给混音用。

## 6. 音效：来源与定调

来源优先级：

1. **产品自己的声音**（提示音、唤醒音、工作声）。用之前先分析频谱：有没有会被听成"嗡嗡声"的持续音、电平是否过高。发现问题先告诉用户。
2. **本地合成**（用 numpy 生成）。完全可控、没有授权问题。
3. **授权素材库**。许可证记进 `brief/licenses.md`；需要账号的网站由用户自己下载。

**定调**：有音高的音效（提示音、上滑音、木槌音）都要和配乐同一个调。实测出音乐的主音后，把合成音效的基准音调到主音上（例如 E 调用 E3 = 164.81 Hz），提示音落在属音（五度）上。音乐换了，就重新定调。

## 7. 旁白（广告片和需要讲解的片子）

### 什么时候配

- 配：带口播的广告、操作教程、步骤多的解说、需要无障碍版本时。
- 不配：字幕已经讲清楚、产品主打安静、主要在静音信息流里播放、或者达不到下面的质量要求时。

### 写旁白稿

- 不逐字重复屏幕上的字，也**不增加新的说法**。旁白同样要过合规检查（见 `09-compliance.md` 第 2、3 节）。
- 长度按语速算：中文约每分钟 220–260 字，英文约每秒 2.5 个词（经验值，按选定的声音实测）。
- 旁白稿和画面一起定稿，留出呼吸的空隙。

### 选 AI 声音

1. 挑 3 个候选声音，用同样的 2–3 句台词各生成一版；有条件的话加一版真人录音做对照。
2. **把所有样本的响度对齐**（比如都调到 −18 LUFS），否则大声的那版总显得"更好"。
3. **盲听 A/B**：隐藏名称、打乱顺序，请用户选。
4. 只有用户分不出哪个是合成的、或者明确更喜欢合成版时，才用 AI 声音。
5. 核对语音服务的商用授权，按规定标识合成语音。
6. 检查每句生成的**时长**（合成语音偶尔会拖得很长或吞字），随机种子不好就换一个重生成。
7. 时间紧时，先找电脑里已经装好的本地语音模型，再考虑排队的公共演示站。

### 绝对不做

- **不克隆任何真人的声音**，除非本人书面同意且用途在同意范围内；不模仿公众人物的声音（法律依据见 `09-compliance.md` 第 6 节）。
- 不用真人声音样本去"微调"一个相似的声音。

旁白出现的时段，音乐要让路（第 8 节的窗口压低）。

## 8. 混音：按时间窗测量

在**完整混音**上判断，不在单独的音轨上判断。按时间窗测量，不靠耳朵，也不靠一个总音量推子。

1. **读出时间窗**：从时间线和音效报告里读出每个重要声音的时段，比如标注组、产品声音、提示音、旁白，写成 `sound/windows.json`。窗口跟着时间线走，重剪之后重新生成。
2. **测量**每个窗口里"音效减音乐"的 dB 差。**短促的提示音按每个事件约 60 ms 的短窗逐个测**，不看整段平均：整段平均会把被盖住的单个提示音藏起来。案例里一个标注段按整段平均改善了约 8 dB，逐个测时每个提示音仍比音乐低 10–16 dB。
3. **先给音乐整体衰减**约 3 dB（整片一个值）。
4. **在窗口内再压低音乐**（ducking，闪避）。下面的数是窗口内闪避的**总量**，相对于没有预先压低过的音乐分轨，不含第 3 步的整体衰减：标注组约 −5 dB，产品自己的声音约 −8 dB，较轻的环境提示约 −5 dB，旁白段按需要 −8 到 −12 dB。如果音乐分轨在做的时候已经在某段预先压低过（比如剪音乐时就给某段让了 2 dB），窗口里只写剩下的差额，否则会压过头；反过来，照搬别人"在已压过的分轨上再压几 dB"的数字，会压不够。每次压低都用约 0.6 秒的升余弦渐变，听不出音乐突然掉下去。
5. **逐个测完，短促的提示音仍比音乐低 8 dB 以上，直接把它提高**（比如 +6 dB），不要继续压音乐，否则音乐会听起来"空掉"。
6. **重新测量**，写进混音报告。
7. 两条音轨相加（不做归一化），加一个轻限幅，然后两遍响度标准化到目标（第 9 节），压成 AAC 256k，画面流直接复制（`-c:v copy`），不重新压缩画面。

附带的混音脚本是 `scripts/audio/mix.py`（参数见 `scripts/audio/README.md`）：整体衰减对应 `--music-gain`，窗口闪避写进 `sound/windows.json` 的 `gain_db`，两者在脚本里按 dB 相加；它的测量表里 `hits` 一列就是逐个提示音的 60 ms 测量。

> 案例：某产品片第一版成片，用户说"音乐太强了"，标注提示音和产品自己的声音都被盖住。实测标注段的音效比音乐低约 30 dB。音乐整体降 3 dB、窗口内再压低之后，按整段平均看已经改善了不少，但逐个按 60 ms 测，提示音仍低 10–16 dB；于是把提示音本身提高 6 dB，多数提示音变成只比音乐低 4–8 dB，"能清楚听到，但不刺耳"。

后处理链要先单独跑通一遍，再接到长时间渲染后面，并优先用环境里已经有的库。否则可能在 1080p 渲染跑完之后才因为缺一个库而崩溃。

## 9. 响度目标

响度用 LUFS（或写作 LKFS，同一个量）表示整体听感有多响，按 ITU-R BS.1770 测量；dBTP 是真峰值。下表是 2026-10 核对的数值，**投放前按平台和标准的最新文档再核对一次**：

| 场景 | 整体响度 | 真峰值上限 | 来源 / 说明 |
|---|---|---|---|
| 网络视频通用（官网、社交平台、聊天转发） | −16 LUFS | −1.5 dBTP | 本 skill 的默认值；比 −14 安静一点，留有余量 |
| 流媒体平台（YouTube、Spotify 等） | 约 −14 LUFS | −1 dBTP | 平台会把更响的内容调小，较安静的一般不调大 |
| 中国网络视听节目 | −15 LKFS（嘈杂环境收听）或 −24 LKFS（安静环境），容差 ±2 LU | −1 dBTP | GY/T 377—2023《网络视听节目音频响度技术要求和测量方法》 |
| 中国电视 | −24 LKFS，容差 ±2 LU | — | GY/T 282—2014（GY/T 379—2023 引用） |
| 欧洲广播 | −23 LUFS | −1 dBTP | EBU R128 |
| 美国广播 | −24 LKFS | −2 dBTP | ATSC A/85 |
| 现场路演、投影 | 母版按 −16 出 | −1.5 dBTP | 现场音量用播放设备调，不要为了"响"把母版压到 −10 |

短视频平台（抖音、TikTok、Instagram、视频号等）没有公开的统一数值，按 −14 到 −16 LUFS、真峰值 −1 dBTP 交付，上传后在手机上实听。

用 ffmpeg 测量（ffmpeg 可以从 `imageio-ffmpeg` 取）：

```bash
ffmpeg -hide_banner -i final.mp4 -af ebur128=peak=true -f null -   # read "I:" (integrated) and "Peak:" in the summary
```

## 10. 交付前的声音检查

- [ ] 整体响度和真峰值达标，没有削波；
- [ ] 每个提示音和它的画面事件对齐（误差不超过 1 帧）；
- [ ] 每个接点（音乐交叉、窗口压低）前后听一遍，没有鼓包、没有突然的空洞；
- [ ] 没有一层从中段一直响到结尾的底噪；
- [ ] 在手机外放和耳机上各听一遍（手机外放几乎没有低音，低频为主的提示音可能听不见）；
- [ ] 片尾音乐结束在完整的乐句上，声音和画面同时结束；
- [ ] 授权文件和片尾署名一致。
